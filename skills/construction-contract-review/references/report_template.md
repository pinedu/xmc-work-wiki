# 审查报告格式说明

交付给用户的报告 = 引擎 `--format md` 的输出**原样直接输出到聊天面板**（v1.3.2 起不再保存为报告文件），不改写结构。固定结构如下：

1. **标题与引擎信息**：报告标题 + 引擎版本 + 规则版本（可追溯到具体规则集）。
2. **审查概览**：条款总数、风险发现总数、三级风险计数、总体判断。
3. **风险类型分布**：按风险类型归并，显示每种类型的最高等级。
4. **风险明细**：按严重程度排列（重大 → 较大 → 一般，同级按规则号排序）。每条包含：等级、规则名与规则号、所在条款、风险类型、法规依据（全称+条号）、修订建议、判定依据（命中关键词）。
5. **说明**：确定性声明 + 覆盖范围边界声明（不构成全部法律问题的判断，重大事项建议咨询执业律师）。

## 为什么报告结构也要固定

报告由 `render_markdown()` 从脚本输出确定性渲染（固定排序、固定措辞模板），模型不参与排版。这样"同一份合同"不仅结论一致，连报告文本也是逐字节一致的——审计、留档、前后对比都不会漂移。

## v1.3.2 交付方式说明

- 报告**不落盘为文件**：拿到 `--format md` 输出后原样打印在聊天面板即完成交付；
- 中间文件（stage1.json / verdicts.json）一律放系统临时目录，交付后立即删除；
- 用户事后明确要求留档时才保存文件——这是例外路径，不是默认行为。
