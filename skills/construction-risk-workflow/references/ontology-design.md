# 建筑领域业务 Ontology 设计

> 本文件是 `construction-risk-workflow` skill 的参考文档。三层本体：概念建模层（六大根概念）、属性/关系层（语义网络+欠薪专属关系网）、约束规则层（逻辑锁+状态机）。Phase 4 绘制法律关系图、Phase 3 边界攻击利用关系层信息时检索。

---

本文档属于系统知识底座层，为主Agent的L1情境感知层提供概念素材与关系网络，为L3规则校验层提供结构约束与逻辑锁。
主Agent的L2开放推理层在生成策略时，**必须以本文档为语义基础进行情境理解**，但不得将概念归类当作策略生成的唯一依据。Sub-Agent的第一重校验（语义合规性）以本文档为对照标准。
> **关键原则**：Ontology是"建筑领域的字典和语法"，不是"标准答案"。Agent借助它理解项目，但不能被它限制推理空间。
第一层：概念建模层 —— 建筑领域本体骨架
设计目标
这一层只回答三个问题：
建筑领域里，最顶层的"大类别"有哪些？
每个大类别往下，按什么标准继续细分？
同一层级下的兄弟类别，会不会"你中有我、我中有你"？（要求互斥、不交叉）
顶层五大根概念
建筑领域纷繁复杂，我们提炼出五个互不相交的顶层视角：
建筑领域
├── 建筑实物        ← 物理存在与空间
├── 参与主体        ← 人与组织
├── 建筑活动        ← 全生命周期事件
├── 建筑资源        ← 被消耗的要素
├── 建筑信息        ← 知识与文件
└── 建筑风险        ← 不确定性及其影响
关键原则：这五个根概念之间是严格互斥的。一个东西不会同时既是"实体"又是"活动"；一份合同属于"信息"，而不属于"实体"或"资源"。
一、建筑实体
划分标准：按存在形态与尺度层级，从宏观到微观。
建筑实体
├── 场地                    ← 建筑活动的物理基底，包括土地、室外环境
├── 建筑物                  ← 具有围合空间的、可独立使用的完整人工建造物
├── 建筑空间                ← 建筑物内部被界定出来的、具有特定功能的三维区域
│   ├── 使用空间            ← 供人直接活动的空间（办公室、卧室、教室、商场营业厅）
│   ├── 交通空间            ← 联系各区域的通道（走廊、楼梯间、门厅、电梯厅）
│   ├── 设备空间            ← 容纳机电设备或管线的空间（空调机房、管道井、配电间）
│   └── 辅助空间            ← 支持日常使用的配套空间（卫生间、储藏室、清洁间）
├── 建筑构件                ← 构成建筑物或场地的、相对独立的物理部件
│   ├── 结构构件            ← 承受和传递荷载（基础、柱、梁、楼板、承重墙）
│   ├── 围护构件            ← 分隔室内外环境（外墙、屋面、外门窗、幕墙）
│   ├── 内装构件            ← 室内表面与分隔（内隔墙、地面铺装、吊顶、栏杆）
│   ├── 安装构件            ← 机电末端与嵌入件（灯具、风口、洁具、开关插座）
│   └── 场地构件            ← 室外环境部件（道路、铺装、绿化、围墙、排水沟）
├── 建筑设备                ← 安装在建筑物内、可独立运行的功能性装置
│   ├── 暖通空调设备
│   ├── 电气设备
│   ├── 给排水设备
│   ├── 消防设备
│   └── 智能化设备
└── 建筑系统                ← 由多个构件/设备组合而成、实现特定功能的集合体*
├── 结构系统
├── 围护系统
├── 暖通系统
├── 电气系统
├── 给排水系统
├── 消防系统
└── 智能化系统
关于"建筑系统"的特别说明：系统（如"暖通系统"）与构件、设备不是互斥关系，而是"整体-部分"关系。在第一层我们把它单列出来，是因为在建筑实践中"系统思维"极其重要（如谈能耗必谈系统）。后续在第二层（关系层），我们会用"组成关系"显式表达：暖通系统由哪些风管（构件）、空调机组（设备）组合而成。
二、参与主体（往下展开）
划分标准：按法律身份，先分"人"和"组织"，再在各自内部按职能角色细分。
参与主体
├── 自然人                        ← 具体的人
│   ├── 专业技术人员              ← 提供技术决策与设计（建筑师、结构工程师、机电工程师、造价师）
│   ├── 管理人员                  ← 承担项目管控职责（项目经理、总监、部门经理）
│   └── 作业人员                  ← 现场执行层（木工、电工、焊工、普工、运维技工）
└── 法人组织                      ← 依法设立的企业或机构
├── 建设单位                  ← 发起项目、拥有资产（开发商、政府代建平台、业主单位）
├── 设计单位                  ← 提供设计服务（设计院、设计事务所、专项设计公司）
├── 施工单位                  ← 负责工程建造（总承包企业、专业分包企业、劳务公司）
├── 咨询单位                  ← 提供第三方专业服务（监理公司、造价咨询、招标代理、BIM咨询）
├── 监管单位                  ← 行使公权力监督（住建部门、质监站、消防审查部门）
└── 供应单位                  ← 提供材料与设备（材料生产商、设备制造商、经销商）
设计意图：这里刻意没有把"业主"与"建设单位"混为一谈。现实中业主可能是个人（自然人），也可能是企业（法人），所以"业主"更适合作为角色标签（放在第二层属性/关系层处理），而不是概念层的一个固定类别。
三、建筑活动（往下展开）
划分标准：按项目生命周期的时间顺序。
建筑活动
├── 策划决策活动                ← 项目诞生前的论证与决策（可行性研究、立项审批、选址规划）
├── 设计活动                    ← 将需求转化为技术图纸与模型（方案设计、初步设计、施工图设计、专项设计）
├── 采购活动                    ← 获取资源与服务（招标、投标、材料设备选型、合同签订）
├── 建造活动                    ← 现场实施与安装（施工准备、土建施工、机电安装、装饰装修、调试）
├── 验收活动                    ← 确认成果符合要求（检验批验收、分部分项验收、竣工验收、专项验收）
├── 运维活动                    ← 投入使用后的管理（日常维护、故障维修、能耗管理、空间管理、安全管理）
└── 拆除处置活动                ← 生命周期终点（拆除施工、废弃物处理、场地修复、资源回收）
设计意图：没有把"管理活动"与"技术活动"横向并列，因为现实中它们往往是交织在同一个阶段里的（如施工阶段既有技术活动也有管理活动）。横向并列会导致大量交叉。按时间轴划分，每个阶段内部可以自然容纳管理与技术两类事务。
四、建筑资源（往下展开）
划分标准：按资源形态（被消耗时转化成什么）。
建筑资源
├── 建筑材料                    ← 建造过程中被消耗，最终转化为建筑实体的一部分
│   ├── 结构性材料              ← 承受力学作用（混凝土、钢材、木材、砌体、预应力筋）
│   ├── 功能性材料              ← 提供特定物理性能（防水材料、保温材料、隔音材料、防火涂料）
│   └── 装饰性材料              ← 满足视觉与触觉需求（涂料、瓷砖、石材、金属饰面、玻璃）
├── 施工装备                    ← 建造过程中使用，但不留在建筑内（塔吊、挖掘机、混凝土泵车、脚手架）
├── 人力资源                    ← 投入的劳动与技能（工时、专业工种、技术能力）
└── 资金资源                    ← 投入的资本（建设投资、运营成本、维修基金）
关键区分："施工装备"与"建筑实体"下的"建筑设备"是完全不同的两样东西。施工装备是建造过程中的工具（如塔吊），建完就撤走；建筑设备是交付后留在建筑里运行的（如电梯、空调机组）。如果在概念层混淆，后续所有成本计算、资产管理都会乱套。
五、建筑信息（往下展开）
划分标准：按信息的产生阶段与用途。
建筑信息
├── 设计信息                    ← 表达"要盖成什么样"的技术成果
│   ├── 图纸                    ← 二维表达（平面图、立面图、剖面图、节点详图）
│   ├── 模型                    ← 三维数字化表达（BIM模型、效果图、计算分析模型）
│   └── 技术文件                ← 文字与数据表达（设计说明、计算书、材料清单、技术规格书）
├── 管理信息                    ← 记录"怎么盖、花了多少、改了什么"的过程痕迹
│   ├── 合同文件                ← 权责约定（总承包合同、分包合同、采购合同、设计合同）
│   ├── 过程文件                ← 动态变更（变更通知单、签证单、会议纪要、进度报告、支付证书）
│   └── 验收文件                ← 结果确认（检验记录、竣工图、竣工资料、备案文件）
│   └── 风险处置方案
│       ├── 降级建议书         ← 申请将风险等级予以下调的技术论证与书面建议。
│       ├── 责任切割协议       ← 由相关主体协商或经调解/裁决后签订的权责划分文件。
│       ├── 垫付追偿协议       ← 在风险事件导致紧急资金缺口（如欠薪、伤亡救治、抢险）时，由一方主体先行垫付资金以稳定事态，同时明确垫付款项的追偿对象、方式及期限的法律文件。
│       └── 款项性质认定书      ← 对争议或待处置资金的法律属性与会计科目归属（如工程款、工资、赔偿金、借款、代付款等）进行正式界定和书面确认的管理文件。
└── 规范信息                    ← 行业共识的外部依据（不随单个项目产生，但项目必须遵守）
├── 法律法规                ← 强制性要求（建筑法、消防法、节能条例）
├── 技术标准                ← 技术共识（国家标准、行业标准、地方标准、图集）
└── 企业标准                ← 组织内部要求（设计导则、施工工艺标准、企业图库）
设计意图：把"规范信息"独立出来，是因为它不是某个项目"生出来的"，而是项目"要遵守的"。在后续关系层，我们会建立"某建筑物必须遵守某防火规范"这样的关联，而不是把规范当作建筑物的属性。
六、建筑风险（往下展开）
划分标准：按风险后果的性质/管理维度（这是工程实践中最常用的分类方式，与《建设工程项目管理规范》等标准对齐）。
建筑风险
├── 属性：消除原因（elimination_cause）
├── 自然消除（风险随时间消失）
├── 措施消除（通过工程措施解决）
├── 法律消除（通过司法程序确认不存在）
└── 转移消除（责任转移给其他主体）
├── 安全风险                    ← 导致人员伤亡、健康损害或财产损失
│   ├── 高处坠落风险
│   ├── 物体打击风险
│   ├── 坍塌风险
│   ├── 机械伤害风险
│   ├── 触电风险
│   └── 火灾与爆炸风险
├── 质量风险                    ← 导致工程不合格、功能缺陷或耐久性不足
│   ├── 结构质量风险            ← 承载力、稳定性、裂缝、沉降
│   ├── 防水质量风险            ← 渗漏、潮湿
│   ├── 装饰质量风险            ← 空鼓、色差、平整度
│   ├── 安装质量风险            ← 管线错接、设备运行异常
│   └── 材料质量风险            ← 以次充好、性能不达标
├── 进度风险                    ← 导致工期延误或关键路径中断
│   ├── 设计延误风险
│   ├── 施工组织风险
│   ├── 供应链延迟风险
│   ├── 气候/季节影响风险
│   └── 审批流程延误风险
├── 成本风险                    ← 导致投资超支、收益损失或资金链断裂
│   ├── 工程量变更风险
│   ├── 材料价格波动风险
│   ├── 融资成本变动风险
│   └── 索赔与反索赔风险
├── 合同与法律风险              ← 导致法律纠纷、履约争议或行政处罚
│   ├── 合同条款缺陷风险
│   ├── 分包管理风险
│   ├── 欠薪风险
│   ├── 知识产权风险
│   └── 合规性风险              ← 违反法规、规划条件、环保要求
├── 技术风险                    ← 技术方案不可行、不成熟或应用失败
│   ├── 设计技术风险            ← 方案错误、计算失误、BIM碰撞未检出
│   ├── 施工技术风险            ← 工艺不适用、新技术失败
│   ├── 材料技术风险            ← 新材料性能不稳定
│   └── 设备技术风险            ← 设备选型错误、系统不兼容
└── 环境与社会风险              ← 自然环境、周边社区、宏观政策变化
├── 自然灾害风险            ← 地震、台风、洪水、地质灾害
├── 场地环境风险            ← 地下障碍物、污染土、水文地质异常
├── 周边影响风险            ← 对邻近建筑的损害、交通干扰、噪音投诉
└── 政策与市场风险          ← 规划调整、限购政策、市场需求变化
概念定义
建筑实体
根概念
[TABLE]
| 概念 | 定义 | 边界说明 |
| 建筑实体 | 建筑领域中一切占据物理空间、可被感知或测量的客观存在物的总称。 | 不包括人、组织、活动、文件、资金等非物质对象；也不包括尚未物化的抽象方案。 |
[/TABLE]
一级子概念定义
场地
定义：建筑物赖以存在的物理基底及其直接关联的室外环境的总称。边界：以用地红线为界，包含地表、地下一定深度及地上开放空间；不包括建筑物本体。
建筑物
定义：由人工建造的、具有围合空间且能独立实现特定功能的完整构造物。边界：必须是完整的、可独立使用的单体或群体（如一栋楼、一个场馆）；不包括构筑物（如围墙、烟囱）——构筑物归入"场地构件"或"建筑构件"。
建筑空间
定义：建筑物内部经围合或限定形成的、具有特定功能属性的三维区域。边界：是"区域"而非"物理外壳"；同一物理外壳内可划分出多个空间（如一个大开间用隔断分成两个办公室）。
建筑构件
定义：构成建筑物或场地的、在物理上可辨识、可独立描述的部件或单元。边界：是"组成材料"与"完整建筑物"之间的中间层级；一块混凝土不是构件，但一根柱、一扇窗是构件。
建筑设备
定义：安装在建筑物内部、可独立运行以实现特定建筑功能的装置或机组。边界：与"建筑构件"的核心区别是可运行、可启停、有动态功能；与"施工装备"的核心区别是交付后留在建筑内长期使用。
建筑系统
定义：由多个建筑构件或建筑设备按功能逻辑组合而成、协同工作以实现特定建筑功能的集合体。边界：不是物理上独立的新物体，而是"功能视角的重组"；一个空调机组是设备，但"整栋楼的暖通系统"是系统。
二级子概念定义
建筑空间 的四个子类
[TABLE]
| 概念 | 定义 | 互斥边界 |
| 使用空间 | 供人员开展主要活动或实现建筑核心功能的空间。 | 是建筑存在的"目的"；与交通空间的边界是：人停留在此是为了完成某件事，而非"经过此处去别处"。 |
| 交通空间 | 联系各功能区域、承担人流或物流通行功能的空间。 | 包括水平交通（走廊）和垂直交通（楼梯间、电梯厅）；与使用空间的边界是：人经过此处是为了到达另一处。 |
| 设备空间 | 容纳建筑机电设备、管线系统或配套设施的空间。 | 通常不对外直接开放，或仅由专业人员进入；与辅助空间的边界是：设备空间以"容纳机器"为主，辅助空间以"支持人的日常活动"为主。 |
| 辅助空间 | 支持日常运行但非核心活动直接使用的配套空间。 | 如卫生间、清洁间、储藏室；与使用空间的边界是：没有这些空间，主体功能仍可部分运转，但体验或效率大幅下降。 |
[/TABLE]
建筑构件 的五个子类
[TABLE]
| 概念 | 定义 | 互斥边界 |
| 结构构件 | 承受和传递荷载、维持建筑物力学稳定性的构件。 | 如果移除会导致建筑倒塌或变形超限；包括基础、柱、梁、楼板、承重墙。 |
| 围护构件 | 分隔建筑物内外环境、抵御自然因素（风、雨、热、声）影响的构件。 | 位于建筑最外边界；包括外墙、屋面、外门窗、幕墙。 |
| 内装构件 | 覆盖或分隔室内界面、满足使用与美观需求的构件。 | 位于建筑内部，不直接承受主要结构荷载，也不直接抵御室外环境；包括内隔墙、地面铺装、吊顶、栏杆。 |
| 安装构件 | 建筑机电功能在室内的末端呈现部件或嵌入件。 | 是设备系统的"终端触角"，本身不可独立运行，但属于建筑完成面的一部分；包括灯具、风口、开关插座、洁具。 |
| 场地构件 | 构成室外场地环境、服务于交通、景观或市政功能的部件。 | 位于场地范围内，不属于任何建筑物本体；包括道路、铺装、绿化、围墙、排水沟。 |
[/TABLE]

参与主体 —— 第一层概念定义
根概念
[TABLE]
| 概念 | 定义 | 边界说明 |
| 参与主体 | 在建筑全生命周期中，以决策、执行、监督、供应或投资等身份介入，并对建筑活动产生实质影响的自然人或法人组织的总称。 | 不包括建筑实体本身（如"建筑物"不是主体），也不包括抽象角色（如"业主"是角色标签，主体是具体的人或组织）。 |

一级子概念定义
1. 自然人
定义：具有完全或限制民事行为能力的、以个人身份参与建筑活动的具体人类个体。边界：以"个人"身份出现；即使受雇于企业，其"自然人"身份与"企业雇员"身份分离。
2. 法人组织
定义：依法设立、具有独立民事权利能力和行为能力、以组织名义参与建筑活动的企事业单位或机构。边界：必须是依法登记的组织实体；不包括临时拼凑的班组（班组归入"人力资源"下的组织形式，而非独立法人）。

自然人 的三个子类
[TABLE]
| 概念 | 定义 | 互斥边界 |
| 专业技术人员 | 凭借注册资格或专业技术能力，为建筑活动提供技术决策、设计、计算或咨询服务的自然人。 | 以"技术输出"为核心价值；与作业人员的边界是：不直接从事体力劳动，而以脑力/专业判断为主。 |
| 管理人员 | 在建筑活动中承担计划、组织、协调、控制职责，对资源或过程行使管理权的自然人。 | 以"管理行为"为核心；与技术人员的边界是：不一定提供技术方案，但负责方案的实施组织与进度/质量/成本控制。 |
| 作业人员 | 在建筑活动一线，通过体力劳动或操作技能直接改变建筑实体状态或完成具体工序的自然人。 | 以"执行操作"为核心；包括技术工人（电工、焊工）与普通工人；与管理人员的边界是：不拥有对项目整体或班组的指挥权。 |

| 设计单位 | 受建设单位委托，将功能需求转化为技术图纸、模型与文件的法人组织。 | 以"智力成果交付"为主；与咨询单位的边界是：直接产出设计文件，而非仅提供第三方意见。 |
| 施工单位 | 受建设单位或总承包方委托，通过现场建造活动将设计转化为建筑实体的法人组织。 | 以"物理建造"为核心；包括总承包企业与专业分包企业。 |
| 咨询单位 | 受委托提供第三方专业智力服务，辅助决策、监督或管理的法人组织。 | 不直接设计，也不直接施工；包括监理、造价咨询、招标代理、BIM咨询等。 |

| 供应单位 | 向建筑活动提供材料、设备或构配件的生产商、经销商或租赁商。 | 以"产品/物资交付"为核心；与施工单位的边界是：不直接参与现场建造安装（除非同时是施工单位）。 |
[/TABLE]

根概念
[TABLE]
| 概念 | 定义 | 边界说明 |
| 建筑活动 | 在建筑全生命周期中，由参与主体发起或执行的、导致建筑实体状态改变、建筑资源消耗或建筑信息产生的事件与过程的总称。 | 不包括主体内部的管理培训（与建筑项目无直接关联），也不包括建筑实体交付后的纯使用行为（如"在办公室里办公"不是建筑活动，但"维修办公室空调"是）。 |

一级子概念定义（按生命周期顺序）
[TABLE]
| 概念 | 定义 | 互斥边界 |
| 策划决策活动 | 在建筑实体形成之前，围绕项目必要性、可行性、投资规模与建设方案所开展的论证、评估与审批过程。 | 以"项目是否值得做、能不能做"为核心；与设计的边界是：不产出具体技术图纸，只产出决策结论。 |
| 设计活动 | 将建设单位的功能需求与技术条件，转化为可指导建造的图纸、模型与技术规格的创造性技术过程。 | 以"技术表达"为核心；与采购的边界是：设计确定"买什么规格"，采购确定"从谁那里买"。 |
| 采购活动 | 依据设计成果与项目计划，通过市场选择、交易谈判与合同签订获取资源或服务的过程。 | 以"交易达成"为核心；与建造的边界是：采购完成时建筑实体尚未改变。 |
| 建造活动 | 在场地范围内，通过现场施工与安装将设计意图转化为物理建筑实体的过程。 | 以"物理实现"为核心；是建筑实体从"无"到"有"或从"旧"到"新"的关键阶段。 |
| 验收活动 | 依据合同约定与技术标准，对建筑实体、建筑信息或建筑活动成果进行检验、确认与接收的过程。 | 以"合格确认"为核心；与运维的边界是：验收是"交钥匙"前的把关，运维是"交钥匙"后的管理。 |
| 运维活动 | 建筑实体交付使用后，为保障其功能持续、性能稳定与资产保值所开展的管理、维护与更新过程。 | 以"持续保障"为核心；与拆除的边界是：运维是"延长寿命"，拆除是"终结寿命"。 |
| 拆除处置活动 | 当建筑实体达到生命周期终点或功能废弃时，通过解体、清运与场地恢复使其退出物理存在的过程。 | 以"终结与回收"为核心；是建筑实体生命周期的终点。 |
[/TABLE]

[TABLE]
| 概念 | 定义 | 互斥边界 |
| 安全风险 | 导致人员伤亡、健康损害或突发财产损失的不确定性。 | 以"人身安全"为核心；与质量风险的边界是：安全风险强调"突发/急性"后果，质量风险强调"缺陷/慢性"后果。 |
| 质量风险 | 导致建筑实体功能缺陷、性能不达标或耐久性不足的不确定性。 | 以"实体缺陷"为核心；与进度风险的边界是：质量风险不必然导致工期延误（可能返工，也可能带病验收）。 |
| 进度风险 | 导致建筑活动关键路径延长或工期目标无法实现的不确定性。 | 以"时间偏离"为核心；与成本风险的边界是：进度风险可能导致成本增加，但核心损失是"时间"。 |
| 成本风险 | 导致投资超支、收益损失或资金链断裂的不确定性。 | 以"资金偏离"为核心；与合同风险的边界是：成本风险是"钱不够"，合同风险是"约定不清导致纠纷"。 |
| 合同与法律风险 | 因合同条款缺陷、履约失败或法律合规问题导致权利义务争议或行政处罚的不确定性。 | 以"法律后果"为核心；是"约定/规则层面"的风险，而非"物理层面"的风险。 |
| 技术风险 | 因技术方案不可行、不成熟或应用失败导致目标无法实现的不确定性。 | 以"技术失败"为核心；与质量风险的边界是：技术风险是"方案本身有问题"，质量风险是"执行后实体有问题"。 |
| 环境与社会风险 | 因自然环境变化、场地条件异常、周边干扰或宏观政策市场变动导致目标偏离的不确定性。 | 以"外部性"为核心；是项目外部因素引发的风险，而非项目内部管理因素。 |
[/TABLE]
二级子概念定义（合同与法律风险）
[TABLE]
| 概念 | 定义 | 互斥边界 |
| 合同条款缺陷风险 | 因合同文本约定不明、遗漏重要事项或权利义务失衡，导致履约争议的可能性。 | 以"文本缺陷"为核心；与分包管理风险的边界是：条款缺陷是"写错了"，分包风险是"管错了"。 |
| 分包管理风险 | 因分包单位选择不当、管控失效或层层转包，导致工程质量、安全或进度失控的可能性。 | 以"分包链条失控"为核心；是合同履行过程中的管理风险。 |
| 欠薪风险 | 因资金链断裂、支付链条冗长或恶意拖欠，导致作业人员劳动报酬无法按时足额支付的可能性。 | 以"劳动报酬支付失败"为核心；与成本风险的边界是：欠薪是"该付的钱没付"（法律/社会问题），成本风险是"总预算超支"（财务问题）。 |
| 知识产权风险 | 因设计成果侵权、技术方案抄袭或品牌标识冲突，导致法律索赔或项目停滞的可能性。 | 以"智力成果权属争议"为核心。 |
| 合规性风险 | 因建筑活动违反法律法规、规划条件、环保要求或行政许可，导致行政处罚或项目叫停的可能性。 | 以"违反强制性规定"为核心；与合同条款缺陷的边界是：合规风险是"违反了外部法律"，条款缺陷是"内部约定有问题"。 |
[/TABLE]
第二层：属性/关系层 —— 建筑领域本体语义网络
一、第二层设计总原则
[TABLE]
| 原则 | 说明 |
| 属性即特征 | 描述一个概念"自己长什么样"——名字、大小、时间、状态 |
| 关系即关联 | 描述两个概念"怎么互动"——谁包含谁、谁作用于谁、谁影响谁 |
| 方向必须清晰 | 每个关系都有"从谁出发、指向谁"，且尽量给出逆关系（如"管理" ↔ "被管理"） |
| 不跨根乱连 | 关系主要发生在不同根概念之间；同一根概念内部的关系（如"建筑物包含空间"）用层级隐含，不额外命名 |
| 风险横切一切 | 建筑风险与其他五个根概念都有关系，这是本体的核心网络 |
[/TABLE]

四、关键关系精确定义（避免歧义）
以下是在实际应用中最容易混淆的几组关系，第二层必须明确区分：表格
[TABLE]
| 关系对 | 正向关系 | 逆向关系 | 边界说明 |
| 建筑物 vs 建筑构件 | 建筑物 由...组成 建筑构件 | 建筑构件 是...的部分 建筑物 | "组成"是物理构成关系；一个构件只能属于一个建筑物（通常） |
| 建筑物 vs 建筑设备 | 建筑物 安装有 建筑设备 | 建筑设备 安装于 建筑物 | "安装"是交付后的固定关系；施工装备不建立此关系 |
| 建筑构件 vs 建筑系统 | 建筑系统 包含 建筑构件 | 建筑构件 属于 建筑系统 | 一个构件可属于多个系统（如楼板既属于结构系统，也可能属于围护系统） |
| 建筑活动 vs 建筑实体 | 建筑活动 作用于 建筑实体 | 建筑实体 被...作用 建筑活动 | "作用"是动态改变；设计活动作用于"图纸"（信息），而非直接作用于实体 |
| 参与主体 vs 建筑活动 | 参与主体 执行 建筑活动 | 建筑活动 由...执行 参与主体 | "执行"是动手做；"管理"是看着做；"监督"是查着做，三者互斥 |
| 建筑风险 vs 建筑活动 | 建筑风险 存在于 建筑活动 | 建筑活动 包含 建筑风险 | 风险不是活动的"产出"，而是活动过程中伴随的不确定性 |
| 建筑资源 vs 建筑实体 | 建筑材料 转化为 建筑实体 | 建筑实体 由...构成 建筑材料 | 转化是单向的：材料消耗后成为实体，不再作为独立资源存在 |
[/TABLE]
五、欠薪风险的专属关系网络（重点）
基于第一层对欠薪风险的定位，第二层为其建立专属关系簇：
欠薪风险
├── 存在于 ←→ 建造活动          （欠薪风险主要存在于施工阶段的工资支付环节）
├── 存在于 ←→ 运维活动          （运维阶段的维保人员工资也可能欠薪）
├── 由...引发 ←→ 施工单位        （总包单位资金链断裂或挪用专户资金）
├── 由...引发 ←→ 劳务公司        （劳务公司截留或拖欠工资）
├── 由...引发 ←→ 建设单位        （建设单位拖欠工程款导致下游欠薪）
├── 影响 ←→ 作业人员（自然人）   （直接影响作业人员的劳动报酬权）
├── 导致损失 ←→ 资金资源         （应支付但未支付的资金）
├── 导致损失 ←→ 人力资源         （劳动力流失、停工、维权成本）
├── 被记录于 ←→ 管理信息（合同）  （劳务合同、工资支付协议）
├── 被记录于 ←→ 管理信息（过程）  （工资专户流水、考勤记录、欠薪投诉单）
├── 受...管控 ←→ 监管单位        （人社部门、住建部门的监察与处罚）
└── 受...管控 ←→ 建筑活动（支付）  （工资支付节点的审核与发放活动）
六、风险降级专属关系簇（建设单位视角）
风险处置文件
├── 降级 ←→ 建筑风险 （降级建议书 降级 欠薪风险）
├── 切割责任 ←→ 参与主体 （责任切割协议 切割 建设单位与总包的责任）
├── 约定垫付 ←→ 资金资源 （垫付追偿协议 约定 垫付资金的追偿路径）
├── 认定性质 ←→ 资金资源 （款项性质认定书 认定 某笔资金的法律属性）
├── 固化证据 ←→ 建筑信息 （风险处置文件 固化 过程文件/合同文件的证据效力）
└── 触发 ←→ 建筑活动 （风险处置活动 触发 工资支付活动/复工活动）
第三层：约束规则层 —— 建筑领域逻辑锁
一、第三层设计总原则
[TABLE]
| 子层级 | 作用 | 通俗解释 |
| 结构约束 | 规定"类与类之间不能怎样" | 一个人不能同时是自然人又是法人 |
| 属性约束 | 规定"特征该怎么填、填几个" | 一个建筑物必须至少有一个空间 |
| 关系约束 | 规定"连线该怎么走、能不能传" | 如果A在B前面，B在C前面，那么A一定在C前面 |
| 复杂规则 | 规定"满足什么条件就推出什么结论" | 如果工程款拖欠+无工资专户，则存在欠薪风险 |
[/TABLE]
二、结构约束（类的逻辑锁）
1. 互斥约束（非此即彼）
以下概念不能同时落在同一个实例上：
┌─────────────────────────────────────────────────────────┐
│  互斥对1：自然人  vs  法人组织                           │
│  ─────────────────────────────────────                   │
│  一个人（如"张三"）不能同时是自然人又是法人组织。         │
│  即使他是"个体工商户"，在本体中也只能选择一种身份归类。   │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  互斥对2：建筑材料  vs  施工装备                         │
│  ─────────────────────────────────────                   │
│  一台塔吊不能同时是"建筑材料"和"施工装备"。               │
│  即使它由钢材制造，它在项目中是"被使用的工具"，不是"被   │
│  消耗的实体组成部分"。                                    │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  互斥对3：使用空间  vs  交通空间  vs  设备空间  vs  辅助空间 │
│  ─────────────────────────────────────────────────────   │
│  同一个建筑空间不能同时被定义为两种功能类型。              │
│  例如：一个"走廊"不能同时是"交通空间"又是"使用空间"。     │
│  （注：多功能厅属于"使用空间"下的子类，而非跨类）        │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  互斥对4：安全风险  vs  质量风险（针对同一风险事件）       │
│  ─────────────────────────────────────                   │
│  同一个已发生的风险事件，其后果性质是确定的：              │
│  "脚手架倒塌砸死人"是安全风险；                          │
│  "混凝土强度不达标"是质量风险。                          │
│  不能将同一个具体事件同时归入两类。                       │
│  （注：一个项目可以同时存在多种风险，但一个具体事件只属于 │
│  一种风险类别）                                           │
└─────────────────────────────────────────────────────────┘
─────────────────────────────────────────────────────────┐
│  互斥对5：结构构件 vs 围护构件 vs 内装构件（交付态）     │
│  ─────────────────────────────────────────────────────   │
│  同一建筑构件（交付后）不能同时属于两个互斥子类。          │
│  例如：一根柱子不能同时是"结构构件"和"围护构件"。         │
│  例外：幕墙中的"立柱"在概念层归为围护构件，其结构功能    │
│        通过第二层"属于结构系统"关系表达，而非概念层双归类。│
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  互斥对6：建造活动 vs 拆除活动（针对同一实体）             │
│  ─────────────────────────────────────────────────────   │
│  同一建筑实体不能同时进行"建造"和"拆除"。                  │
│  逻辑：一个实体要么在生长，要么在消亡。                    │
│  例外：改造项目中"局部拆除+同步新建"应拆分为两个独立活动， │
│        分别关联不同空间或构件，而非同一整体实体。          │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  互斥对7：在建状态 vs 在用状态 vs 停用状态（实体生命周期）  │
│  ─────────────────────────────────────────────────────   │
│  同一建筑实体在同一时刻只能有一种生命周期状态。              │
│  不能既"在建"又"在用"，也不能既"在用"又"待拆除"。          │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  互斥对8：未开始 vs 进行中 vs 已完成（活动状态）           │
│  ─────────────────────────────────────────────────────   │
│  同一建筑活动在同一时刻只能有一种执行状态。                  │
│  已完成的活动不能回退为"进行中"（错误数据需通过"变更记录"  │
│  修正，而非直接修改状态）。                                 │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  互斥对9：重大风险 vs 较大风险 vs 一般风险 vs 低风险       │
│  ─────────────────────────────────────────────────────   │
│  同一建筑风险在同一评估周期内只能有一个风险等级。            │
│  （风险等级可随时间变化，但同一快照时刻只能有一个值）       │
└─────────────────────────────────────────────────────────┘
2. 条件继承约束（动态归类）
┌─────────────────────────────────────────────────────────┐
│  规则1：高度 > 100m 的建筑物 自动继承 "超高层建筑" 特征    │
│  ─────────────────────────────────────────────────────   │
│  条件：某建筑物 的 高度属性 > 100m                         │
│  推导：该建筑物 自动获得 "超高层建筑" 的附加约束：          │
│        - 必须关联 消防专项审查信息                         │
│        - 必须关联 结构抗震专项审查信息                     │
│        - 必须关联 风洞试验或风振舒适度分析信息             │
│  注意：这不是概念层的子类，而是"满足条件即触发附加规则"。  │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  规则2：开挖深度 > 5m 的基坑 自动继承 "深基坑" 特征        │
│  ─────────────────────────────────────────────────────   │
│  条件：某场地中的开挖实体 深度 > 5m                        │
│  推导：自动触发 "深基坑工程" 约束：                        │
│        - 必须关联 专家论证信息                             │
│        - 必须关联 第三方监测信息                           │
│        - 必须关联 应急预案信息                             │
└─────────────────────────────────────────────────────────┘
3. 子类继承约束（子承父业）
如果 某实例 属于 "施工单位"
那么 该实例 自动继承 "法人组织" 的全部属性
且自动继承 "参与主体" 的全部属性
如果 某实例 属于 "建筑物"
那么 该实例 自动继承 "建筑实体" 的全部属性
4. 等价约束（异名同实）
"总承包企业" = "总包单位"（同一法人组织的不同称谓）
"作业人员" = "一线工人"（同一自然人群体的不同称谓）
注意："建设单位" ≠ "业主"
因为"业主"可能是自然人（个人建房），而"建设单位"必须是法人组织
所以两者在第一层分属不同概念，不能等价
三、属性约束（特征的规则锁）
1. 定义域约束（谁才能有这属性）
[TABLE]
| 属性 | 只能属于谁 | 反例（不允许） |
| 身份证号 | 自然人 | 法人组织不能有身份证号 |
| 统一社会信用代码 | 法人组织 | 自然人不能有社会信用代码 |
| 资质等级 | 法人组织 或 专业技术人员 | 普通作业人员不能有资质等级 |
| 建造时间 | 建筑实体 | 建筑活动不能有"建造时间"（建筑活动有的是"起止时间"） |
| 风险等级 | 建筑风险 | 建筑实体不能有"风险等级"（实体有的是"安全状态"） |
| 进场时间 | 建筑资源 | 建筑信息不能有"进场时间" |
[/TABLE]
2. 值域约束（这属性该填什么类型）
[TABLE]
| 属性 | 必须填什么 | 错误示例 |
| 面积 | 大于0的数字 + 单位（㎡） | 不能填"很大"或负数 |
| 发生概率 | 高/中/低 或 0-100%之间的数 | 不能填"可能吧" |
| 生命周期状态 | 只能从固定列表选：在建/在用/停用/待拆除 | 不能填"差不多快好了" |
| 当前状态（活动） | 只能从固定列表选：未开始/进行中/已完成/暂停/取消 | 不能填"正在搞" |
[/TABLE]
3. 条件必填约束（状态驱动）
[TABLE]
| 触发条件 | 必须填写的属性 | 逻辑说明 |
| 建筑活动状态 = "已完成" | 实际完成时间、实际成果 | 没做完就不能叫已完成 |
| 建筑活动状态 = "进行中" | 当前进度百分比、实际开始时间 | 开始了就必须记录起点 |
| 建筑实体生命周期 = "在用" | 竣工验收日期、使用单位 | 投入使用必须有交接 |
| 建筑实体生命周期 = "待拆除" | 安全鉴定报告、拆除方案审批 | 拆之前必须证明该拆了 |
| 建筑风险状态 = "已发生" | 实际损失金额、受损实体、发生时间 | 已发生就必须有"案底" |
| 建筑风险状态 = "已消除" | 消除措施、消除验收人、消除日期 | 消除了必须留下证据 |
[/TABLE]
4. 取值范围约束（枚举锁）
┌─────────────────────────────────────────────────────────┐
│  风险等级 只能从以下集合选取：                             │
│    {重大风险, 较大风险, 一般风险, 低风险}                  │
│  不允许填：高、中、低、严重、轻微 等模糊词                 │
├─────────────────────────────────────────────────────────┤
│  生命周期状态 只能从以下集合选取：                         │
│    {策划中, 在建, 在用, 停用, 待拆除, 已拆除}              │
│  不允许填：差不多快好了、基本完工、暂时不用 等口语         │
├─────────────────────────────────────────────────────────┤
│  活动状态 只能从以下集合选取：                             │
│    {未开始, 进行中, 已完成, 暂停, 取消}                    │
│  不允许填：正在搞、搞完了、停一下 等口语                   │
├─────────────────────────────────────────────────────────┤
│  材质构成 必须从标准材料库选取：                           │
│    {钢筋混凝土, 钢材, 木材, 砌体, 玻璃, 石材, 金属, ...}   │
│  不允许填：好一点的料、进口货、差不多 等模糊描述           │
└─────────────────────────────────────────────────────────┘
5. 数值逻辑约束（数学锁）
┌─────────────────────────────────────────────────────────┐
│  规则4：计划完成时间 ≥ 计划开始时间                        │
│  规则5：实际完成时间 ≥ 实际开始时间（如果已填写）          │
│  规则6：建筑面积 ≥ 各空间面积之和（允许合理公摊误差）      │
│  规则7：合同金额 ≥ 已支付金额 ≥ 0                         │
│  规则8：应付工资总额 = 工资表各条目之和（校验一致性）      │
│  规则9：工资专户余额 ≥ 0（不能为负）                      │
└─────────────────────────────────────────────────────────┘
6. 基数约束（必须填几个、最多填几个）
┌─────────────────────────────────────────────────────────┐
│  规则10：一个建筑物 必须 至少包含 1个 建筑空间             │
│  ─────────────────────────────────────                   │
│  逻辑：没有内部空间的建筑实体是"构筑物"（如烟囱、围墙）， │
│        不属于"建筑物"。因此，只要归类为建筑物，就必须      │
│        至少有一个空间。                                   │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  规则11：一个建筑物 必须 至少包含 1个 建筑构件             │
│  ─────────────────────────────────────                   │
│  逻辑：建筑物必须由物理部件构成，空壳不能称为建筑物。       │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  规则12：一个法人组织 恰好有 1个 统一社会信用代码           │
│  ─────────────────────────────────────                   │
│  逻辑：一企一码，不能多也不能少。                         │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  规则13：一份合同文件 必须 由 至少2个 参与主体 签订         │
│  ─────────────────────────────────────                   │
│  逻辑：合同是双方或多方法律行为，单方文件不是合同。         │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  规则14：一个建筑风险 必须 至少关联 1个 建筑活动 或         │
│        1个 建筑实体                                       │
│  ─────────────────────────────────────                   │
│  逻辑：孤立存在的风险不属于本项目风险。如果某个风险既不在   │
│        任何活动中，也不影响任何实体，则它不应出现在本体内。 │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  规则15：一个建筑活动（除策划决策外）必须 至少消耗 1种      │
│        人力资源                                           │
│  ─────────────────────────────────────                   │
│  逻辑：纯自动化的建筑活动目前不存在，任何活动至少需要人     │
│        参与决策或执行。                                     │
└─────────────────────────────────────────────────────────┘
四、关系约束（连线的规则锁）
1. 逆关系约束（有去有回）
如果 参与主体A "执行" 建筑活动B
那么 建筑活动B 自动 "由...执行" 参与主体A
如果 建筑活动A "产出" 建筑实体B
那么 建筑实体B 自动 "由...产出" 建筑活动A
如果 建筑风险A "影响" 建筑实体B
那么 建筑实体B 自动 "受...影响" 建筑风险A
如果 合同文件A "由...签订" 参与主体B
那么 参与主体B 自动 "签订" 合同文件A
2. 传递性约束（链条能传）
┌─────────────────────────────────────────────────────────┐
│  传递关系1：前序/后继（建筑活动的时序传递）                │
│  ─────────────────────────────────────                   │
│  已知：活动A 是 活动B 的前序活动                          │
│       活动B 是 活动C 的前序活动                          │
│  推导：活动A 也是 活动C 的间接前序活动                    │
│                                                         │
│  示例：基础施工 → 主体结构施工 → 屋面施工                 │
│        那么：基础施工 间接前序于 屋面施工                 │
│        （屋面施工不能直接开始，因为基础还没做）            │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  传递关系2：位于（空间包含的传递）                        │
│  ─────────────────────────────────────                   │
│  已知：建筑构件A 位于 建筑空间B                           │
│       建筑空间B 位于 建筑物C                              │
│  推导：建筑构件A 位于 建筑物C                             │
│                                                         │
│  示例：一根柱子位于会议室，会议室位于3号楼                │
│        那么：这根柱子位于3号楼                            │
└─────────────────────────────────────────────────────────┘
3. 对称性约束（双向等同）
如果 建筑物A "相邻于" 建筑物B
那么 建筑物B 自动 "相邻于" 建筑物A
如果 参与主体A "签订" 合同C，且 参与主体B "签订" 合同C
那么 参与主体A 与 参与主体B 互为合同相对方
4. 函数性约束（一对一）
┌─────────────────────────────────────────────────────────┐
│  规则：一个建筑构件（交付后）最多属于 1个 建筑物           │
│  ─────────────────────────────────────                   │
│  逻辑：一根柱子不能同时是1号楼和2号楼的组成部分。          │
│        （注：生产阶段的"预制构件"可能库存待分配，但一旦   │
│         安装完成，只能属于一个建筑物）                     │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  规则：一份验收文件 恰好对应 1个 验收活动                  │
│  ─────────────────────────────────────                   │
│  逻辑：一份竣工验收报告不能同时对应两次不同的验收活动。     │
│        （但一次验收活动可以产生多份文件）                   │
└─────────────────────────────────────────────────────────┘
5. 反链约束（防止循环）
┌─────────────────────────────────────────────────────────┐
│  反链1：管理关系不能循环                                   │
│  ─────────────────────────────────────                   │
│  如果 A "管理" B，则 B 不能 "管理" A。                    │
│  例如：项目经理管理施工员，施工员不能反过来管理项目经理。   │
│  （注：A和B可以是同一法人组织内的不同自然人）              │
├─────────────────────────────────────────────────────────┤
│  反链2：分包关系不能循环                                   │
│  ─────────────────────────────────────                   │
│  如果 A "分包给" B，则 B 不能 "分包给" A。                │
│  例如：总包分包给A公司，A公司不能再分包回总包。             │
│  且禁止：A分包给B，B分包给C，C再分包给A（闭环转包）       │
├─────────────────────────────────────────────────────────┤
│  反链3：前序关系不能循环                                   │
│  ─────────────────────────────────────                   │
│  活动A是活动B的前序，活动B是活动C的前序，则活动C不能       │
│  是活动A的前序。否则形成"死循环"，项目永远无法完成。       │
└─────────────────────────────────────────────────────────┘
6. 自反约束（自己不能连自己）
┌─────────────────────────────────────────────────────────┐
│  一个建筑实体不能 "相邻于" 自己                            │
│  一个参与主体不能 "签订合同" 自己（单方合同无效）          │
│  一个建筑活动不能 "前序于" 自己                            │
│  一个建筑风险不能 "影响" 自己（风险必须有外部对象）        │
└─────────────────────────────────────────────────────────┘
7. 复合关系推导（链式推理）
┌─────────────────────────────────────────────────────────┐
│  推导链1：分包链条识别                                     │
│  ─────────────────────────────────────────────────────   │
│  已知：总包A "分包给" 分包B                                │
│       分包B "分包给" 劳务C                                 │
│  推导：总包A 对 劳务C 存在 "间接管理责任"                  │
│       且：该链条深度为3层，超过2层即触发 "违法分包预警"    │
│       （依据：《建设工程质量管理条例》禁止再分包）         │
├─────────────────────────────────────────────────────────┤
│  推导链2：责任追溯链                                       │
│  ─────────────────────────────────────────────────────   │
│  已知：欠薪风险 "由...引发" 劳务公司X                      │
│       劳务公司X "分包自" 施工单位Y                         │
│       施工单位Y "承包自" 建设单位Z                         │
│  推导：欠薪风险 "由...连带承担" 施工单位Y                  │
│       欠薪风险 "由...最终保障" 建设单位Z（在欠付工程款范围内）│
├─────────────────────────────────────────────────────────┤
│  推导链3：空间-实体-系统溯源                               │
│  ─────────────────────────────────────────────────────   │
│  已知：设备A "安装于" 空间B                                │
│       空间B "位于" 建筑物C                                 │
│       建筑物C "由...组成" 系统D（如暖通系统）              │
│  推导：设备A "属于" 系统D                                  │
│       （即使第二层没有直接画这条线，也可推导）              │
└─────────────────────────────────────────────────────────┘
五、跨域一致性校验（新增板块）
┌─────────────────────────────────────────────────────────┐
│  校验1：实体-活动-资源三角一致性                           │
│  ─────────────────────────────────────────────────────   │
│  如果 某建筑活动 消耗了 某建筑材料                         │
│  则 该材料 的 "进场时间" 必须 ≤ 该活动的 "实际开始时间"    │
│  且 该材料 的 "质量状态" 必须为 "合格"                     │
│  否则：标记为 "数据矛盾"——材料还没进场就用了，或不合格就用  │
├─────────────────────────────────────────────────────────┤
│  校验2：风险-实体-损失三角一致性                           │
│  ─────────────────────────────────────────────────────   │
│  如果 某建筑风险 状态为 "已发生"                           │
│  则 该风险 必须 至少关联 1个 受损建筑实体                   │
│       或 至少关联 1个 损失建筑资源                         │
│       或 至少关联 1个 受影响参与主体                       │
│  否则：标记为 "幽灵风险"——说发生了，但不知道影响了什么     │
├─────────────────────────────────────────────────────────┤
│  校验3：合同-主体-实体三角一致性                           │
│  ─────────────────────────────────────────────────────   │
│  如果 某合同文件 约定 "建造某建筑实体"                     │
│  则 该合同 的签订方中 必须包含 1个 施工单位                │
│  且 该施工单位 必须 实际执行了 与该实体相关的建造活动      │
│  否则：标记为 "合同悬空"——签了合同没人干活，或干了活没合同  │
├─────────────────────────────────────────────────────────┤
│  校验4：验收-实体-信息三角一致性                           │
│  ─────────────────────────────────────────────────────   │
│  如果 某建筑物 生命周期状态为 "在用"                        │
│  则 该建筑物 必须 关联 至少1份 "竣工验收文件"              │
│  且 该验收文件 状态为 "已批准"                             │
│  否则：标记为 "未验先用"——违法投入使用                     │
└─────────────────────────────────────────────────────────┘
六、状态机约束
建筑活动和建筑实体的状态不是随意跳转的，必须遵循状态机规则：
┌─────────────────────────────────────────────────────────┐
│  建筑实体 生命周期状态机                                   │
│                                                          │
│   策划中 ──→ 在建 ──→ 在用 ──→ 停用 ──→ 待拆除 ──→ 已拆除 │
│     ↑        │       │        │        │                 │
│     └────────┴───────┴────────┴────────┘                 │
│              （允许回退：如在建中发现问题可退回策划）      │
│              （停用后可恢复为在用，需经鉴定）              │
│  禁止跳转：                                                               │
│    - 策划中 不能直接 → 在用（必须经过在建）                │
│    - 在用 不能直接 → 已拆除（必须经过停用和待拆除）        │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  建筑活动 执行状态机                                       │
│                                                          │
│   未开始 ──→ 进行中 ──→ 已完成                            │
│     │         │                                          │
│     └────┬────┘                                          │
│          ↓                                               │
│        暂停 ──→ 进行中（恢复）                            │
│          │                                               │
│          └────→ 取消（终止）                              │
│                                                          │
│  禁止跳转：                                                               │
│    - 已完成 不能 → 未开始（已完成是终点态）                │
│    - 取消 不能 → 已完成（取消了就是取消了）                │
│    - 未开始 不能直接 → 暂停（没开始谈不上暂停）            │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│  建筑风险 管理状态机                                       │
│                                                          │
│   已识别 ──→ 已评估 ──→ 已应对 ──→ 已消除                 │
│     │         │         │                                │
│     └─────────┴─────────┴────→ 已发生（任一阶段都可能突变）│
│                                                          │
│  状态含义：                                                               │
│    已识别：知道有这个风险，但还没评估等级                  │
│    已评估：已确定概率和影响，定了等级                      │
│    已应对：已采取措施（如买保险、改方案、加防护）          │
│    已消除：措施生效，风险解除                              │
│    已发生：风险变成现实，进入损失处理                      │
│                                                          │
│  禁止跳转：                                                               │
│    - 已发生 不能 → 已消除（发生了就是发生了，只能关闭）    │
│    - 未识别 不能 → 已应对（不认识的风险无法应对）          │
└─────────────────────────────────────────────────────────┘
八、约束规则层总图
┌─────────────────────────────────────────────┐
│              第三层：约束规则层                │
├─────────────────────────────────────────────┤
│  结构约束                                    │
│    ├── 互斥：自然人↔法人、材料↔装备           │
│    ├── 继承：施工单位→法人组织→参与主体       │
│    └── 等价：总承包企业=总包单位              │

│  属性约束                                    │
│    ├── 定义域：身份证号只能属于自然人         │
│    ├── 值域：面积必须是正数                   │
│    └── 基数：建筑物至少含1个空间、1个构件     │
├─────────────────────────────────────────────┤
│  关系约束                                    │
│    ├── 逆关系：A执行B ↔ B由A执行             │
│    ├── 传递：前序活动可跨步传递               │
│    ├── 对称：A相邻B ↔ B相邻A                 │
│    └── 函数：一构件交付后只属于一建筑物       │
├─────────────────────────────────────────────┤
│  复杂规则（推理引擎）                         │
│    ├── 欠薪：拖欠+无专户 → 欠薪风险           │
│    ├── 安全：高空+无防护 → 坠落风险           │
│    ├── 质量：未检先用 → 质量风险              │
│    ├── 进度：关键延误+无缓冲 → 进度风险       │
│    ├── 合规：超高层+无消防审 → 合规风险       │
│    └── 校验：建设单位必须关联实体             │
└─────────────────────────────────────────────┘
