# 建筑安全事件处置（建设单位立场）

识别建筑施工现场的安全事件与隐患，以**建设单位（甲方）立场**给出风险判定与处置方案：
不替施工单位做安全方案，而是**识别甲方风险、督促施工单位整改、固化证据、切割责任、避免被牵连**。

## 一、触发场景

用户描述工地安全事件或隐患并要求分析/处置，例如：

- 「脚手架上有人从 5 米高处坠落受伤，没系安全带，脚手架也没验收」
- 「塔吊作业人员无证上岗」
- 「10 层正在浇筑混凝土，模板支撑还没验收，业主催工期，能不能先浇筑再补验收？」
- 「工地缺电工，我有个工人没电工证但干了三年，能让他接临时用电吗？」
- 「深基坑降水没做还在挖土」
- 「临边没有防护栏杆」
- 「三级配电两级漏保没做就送电」
- 「动火作业没办动火证、下面有易燃物」
- 「吊装作业方案没批、司索信号工没证」
- 「工人进入污水井作业，没通风没检测」
- 「活动板房用易燃材料、宿舍内私拉电线」

**不用于**：质量缺陷、工期纠纷、合同条款审查、欠薪（各自归口其它技能）。

## 二、用法

### Stage 1：确定性识别（必做，引擎执行）

用自包含引擎把案情文本转成结构化风险发现，**结论不依赖模型判断**（同一输入永远同一结果）：

```bash
python scripts/safety_engine.py --text "工地3号楼外脚手架高处作业，未设临边防护，脚手架未验收就上人施工"
python scripts/safety_engine.py --file case.txt --format md
python scripts/safety_engine.py --text "动火作业没办动火证" --format json
```

- **v1.2 引擎逻辑**：原文 → 安全属性派生（关键词，否定优先 + 双重否定豁免）→ 阶段识别（pre/during/post）→ 命中 **B1–B26** 规则 → 叠加 **C1–C5** 复合规则 → 映射 **R-B1–R-B26** 处置策略。
- 规则与属性说明见 `references/rules.md`；输出为风险发现（等级 / 责任主体 / 降级空间 / 判定依据 / 案件阶段）+ 复合规则叠加 + 处置策略 + 红线。
- v1.2 输出新增 `stage`（案件阶段）和 `compound_findings`（复合规则）字段。
- **v1.5 新增**（2026-09-14 沉淀）：深基坑监测报警 B25（围护结构位移超预警值）+ 节假日监测中断 B26（feasibility=必须拒绝，含《责任切割协议》强制动作）+ 新属性 `monitoring_continuous`（neg 词含"停测/暂停监测/节假日停测"，pos 词含"24小时监测/第三方监测/值班监测/加密监测"）。



### Stage 2：语义复核（**必做·每案必跑**，由宿主平台 agent 执行）

> **⭐ v1.4 强约束（2026-09-14 沉淀）**：Stage 2 是**无条件必做**——**每一条安全案情都必须经过 Stage 2 语义复核**，**不设触发条件**、**不允许跳过**、**不存在"Stage 1 命中了就无需 Stage 2"的情况**。
>
> **设计原因**：
> - Stage 1 是关键词级确定性判定，**永远可能漏报**（口语化/换说法/绕过关键词）
> - Stage 1 命中不等于结论正确——**仍需语义复核确认**案情确实支持该 finding
> - 即使 Stage 1 未命中任何规则，也**必须**跑 Stage 2——因为 Stage 1 可能漏报
> - 即使案情只有一句话（如"工人从 10 米高空坠落死亡"），**也必须**跑 Stage 2 确认阶段判定（post）和潜在关联规则

**Stage 2 复核清单（每条都做，不分主次）**：

| 复核项 | 检查内容 | 发现问题时的处理动作 |
|---|---|---|
| **A. Stage 1 漏报检查** | 案情含安全违规语义但关键词未命中（如"防护网""密目网""交叉作业""高空坠物"绕过关键词） | 识别漏报后**不擅自归类**到具体规则 → 输出"安全风险待补判"提示 + 建议用户扩展 ATTR_KEYWORD |
| **B. Stage 1 误报检查** | 引擎命中但案情并未支持（如"未佩戴安全帽"被命中但实际案情是"安全帽丢失"非"未佩戴"） | 识别误报后**直接忽略该 finding** + 在结论中标注"已剔除误报 X 条" |
| **C. "经验/年限"陷阱检查** | "干了三年没证""老师傅了不需要证"等用经验替代资质的话术 | **不发明新规则**，但在结论先行段拆穿"经验 ≠ 资质"，强化持证要求 |
| **D. "业主催工期"等施压因素检查** | "9 月底必须开放""业主催""能不能先做了再说"等明示施压 | **不发明规则**，但在处置策略中强化"不得以工期为由降低安全标准"+ 切割商业节点与工程节点 |
| **E. 双重否定 / 换说法 / 否定句式检查** | "不是没戴安全帽""并非未系""密目网"作为"安全网"同义词 | 识别后**不擅自归类** → 提示扩展 ATTR_KEYWORD |

**Stage 2 必做项（4 项，缺一不可）**：

1. ✅ **读 Stage 1 输出 + 读案情原文**——不能仅凭引擎 JSON 推断，必须回到原文
2. ✅ **逐条检查 A/B/C/D/E 复核清单**——每项都必须给出明确结论（"已识别""未识别""不适用"）
3. ✅ **如发现漏报/误报/陷阱/施压，在 Stage 3 输出前修正**——可调整处置策略表述（不算发明规则）
4. ✅ **Stage 2 执行结果必须明示在 Stage 3 输出中**——通过"结论先行段"或"判定说明"标注（但**不能暴露内部字段**）

**执行铁律**：
- ❌ **禁止跳过 Stage 2**——任何案情（包括 Stage 1 命中 0 条规则的案情）都必须跑
- ❌ **禁止发明新规则**——只能在 B1–B23 / C1–C5 内纠偏
- ❌ **禁止把绕过关键词的语义直接归类到具体规则**——这是新增规则的边界
- ✅ **可以指出"漏报"事实**——但要明确标注"建议扩展 ATTR_KEYWORD 覆盖此场景"
- ✅ **可以强化处置策略表述**——但不改变规则匹配逻辑

**反例 1（2026-09-14 真实案例）**：用户问"能不能让总包把6层以下防护网先拆了"——早期版本曾**跳过 Stage 2**（因为案情"看着像安全题就直接答了"），导致输出方案中**违规归类**到 B1+B3+C3。**正确做法**：先跑 Stage 2，识别出"防护网"是漏报 → 指出"原文同时命中'6 层'+'拆防护网'+'交叉干'"构成主动降低安全标准 → 在 v1.3 中扩展 ATTR_KEYWORD 新增 B22/B23 → 后续类似案情引擎直接命中。

**反例 2**：Stage 1 命中 3 条规则（如 v1.0 原始案例 B1+B2+B3），agent 认为"命中了就不必跑 Stage 2"——**错误**。**正确做法**：仍然必跑 Stage 2，因为：
- 可能存在 C/D 触发（案情中可能有"业主催工期"等施压因素，但 Stage 1 不识别）
- 可能存在 B 误报（Stage 1 误命中某条规则，需剔除）
- 必须在结论中标注 Stage 2 执行结果（满足"必做项第 4 条"）

> **⭐ 用户追问纪律（2026-09-14 沉淀）**：当用户追问"X 触发需要条件吗 / X 是必做吗 / Y 的依据是什么"等规则文本核对类问题时，**禁止凭印象写"应该/可能/大概"**——必须先 `skill_view()` 重读 SKILL.md 把原文核对清楚再如实回答。如果发现规则文本写得过于狭窄（如 v1.2 旧版本 Stage 2 触发场景只列了 2 个），**如实承认是设计缺陷**并立即修补 SKILL.md，**不要掩盖或转移话题**。

引擎是关键词级确定性判定，**口语化 / 换说法 / 否定句式 / 双重否定**可能漏判或误判。宿主 agent **必须**（每案必跑）对 Stage 1 结果做一次语义复核：读取案情与引擎输出，判断是否有①漏报（文本已
明确表达但引擎未命中的情形）、②误报（引擎命中但案情并未支持）。**不发明新规则**，只在 B1–B23 / C1–C5 内纠偏。
LLM 调用**不写进本技能**——各平台 agent 自行接入。


### Stage 3：对外输出（必做，按模板）

Stage 1/2 完成后，**对外方案必须按** `templates/output-template.md` **v1.3 模板输出**。模板固定 6 节结构：

1. **案件阶段标签**（pre/during/post/unknown，按引擎 `derive_stage()` 输出）
2. **风险发现**（N 项，按等级排序，每项含等级 / 主体 / 降级空间 / 判定依据）
3. **处置策略**（与风险发现一一对应，每条含 3 步动作 + 时效 + 作用）

2.5. **场景叠加判定**（仅在多风险协同放大时启用）
3. **处置红线**（固定 5 条零容忍事项，按 SKILL.md 第四节措辞）
4. **阶段适配处置建议**（4 个分支：pre/during/post/unknown）
5. **证据封存清单**（每项风险对应证据表，含名称/来源/固化时点/责任人）
6. **关键信息确认**（可选，用户输入信息不足时启用 `clarify` 追问 2~4 个问题）

**模板红线**（违反任一视为执行事故）：

- ❌ **禁止对外暴露规则编号**（`[B1]`、`[R-B2]`、`[C3]` 等仅内部溯源）
- ❌ **禁止对外暴露引擎字段**（`stage`、`compound_findings`、`COMPOUND_RULES` 等）
- ❌ **禁止对外暴露 Phase 标注**（`[Phase 1]`、`[SC-8]` 等内部执行标记）
- ❌ **禁止给出泛化建议**（如"加强安全管理"），必须给出可执行的"动作 + 文书"组合
- ❌ **禁止删减处置红线的 5 条**
- ❌ **禁止跳过阶段适配**（post 阶段必须联动 `rhzy-skill4-incident-duty-allocation` + 启动事故上报）

模板已内置正反例与填充规则，详见 `templates/output-template.md` v1.2。

| 叠加规则                    | 联动基础规则   | 风险升级 |
| ----------------------- | -------- | ---- |
| C1 动火 + 消防不到位 → 重大火灾    | B9 + B13 | 重大   |
| C2 移动平台 + 高处作业 → 重大坠落   | B11      | 重大   |
| C3 模板未验收 + 浇筑混凝土 → 重大坍塌 | B8       | 重大   |
| C4 临建违规 + 人员密集 → 重大群死群伤 | B15      | 重大   |
| C5 起重违规 + 高处作业 → 重大复合伤害 | B10      | 重大   |



### 支持的阶段识别

- `pre`（事前·隐患阶段）→ 用《整改通知单》
- `during`（事中·违规进行中）→ 用《停工令》
- `post`（事后·已发生事故）→ **联动** `rhzy-skill4-incident-duty-allocation`
- `unknown`（未识别）→ 补问用户



### 支持的语言特性

- **否定优先**：避免"没有安装临边防护"里的正向子串"安装临边防护"被误判为 True
- **双重否定豁免**：识别"不是没戴安全帽"= 戴了
- **阶段字段**：自动识别 pre/during/post，联动不同处置路径



## 四、处置红线（安全场景，零容忍）

- 不得建议**瞒报、迟报、隐匿**事故——依法按时限报告。
- 不得建议在隐患未消除前**继续施工作业**。
- 不得以内部协议**免除建设单位依法应尽的安全生产管理 / 报告责任**。
- 《责任切割协议》仅有**内部追偿效力**，不得对抗从业人员及监管部门。
- 证据固化优先：现场影像、监控、旁站、验收与整改记录应及时封存备查。



## 五、边界

- 本技能聚焦**安全**情形；质量、工期、合同、欠薪请走对应归口。
- 已覆盖 21 类高频隐患 + 5 类场景叠加。如需扩展其它安全判据（消防验收、特种设备、环保等），在 `scripts/safety_engine.py` 的 `ATTR_KEYWORD` 增补属性关键词、在 `RULES` 增补规则、在 `COMPOUND_RULES` 增补复合规则（并在 `references/rules.md` 记档）即可。



## 六、扩展引擎的纪律（v1.3.0 更新）

扩展引擎时**必须**遵循的工作纪律（违反任一视为执行事故）：

1. **probe 先于凭印象**（Pitfall 1/2）：新增属性前先看本机档案/历史会话中的同类词表，**禁止凭印象写 neg/pos**——口语变体（还没/尚未/缺）必须穷举。
2. **子串冲突必查**（Pitfall 3）：新增 pos 词时必须检查 `neg + pos子串` 冲突（如"无三级配电"包含"三级配电"）。
3. **窗口含短语首字符**（Pitfall 4）：双重否定豁免的窗口必须 `idx + 1`，否则"不是没戴"无法识别。
4. **通用+子类 pos 同步**（Pitfall 5）：子类词必须同时入通用属性和子类属性的 pos，否则双规则不会同时命中。
5. **⭐ 属性方向必判**（Pitfall 8·v1.3 新增）：新增属性前先判定"问的是合规还是违规"——主动违规动作（拆防护网）的违规词入 pos，**不是 neg**。
6. **⭐ conditions 方向匹配**（Pitfall 9·v1.3 新增）：新增规则时检查 `attr_true` / `attr_false` 与属性的 pos/neg 方向匹配——违规属性必须用 `attr_true`。
7. **回归测试强制**（Pitfall 7）：修改 `ATTR_KEYWORD`/`RULES` 后**必须**跑 `python scripts/test_engine.py`，通过率 ≥ 95% 才合并。
8. **阶段关键词保守**（Pitfall 6）：避免过宽动词（"作业"），扩展时优先负面词（未办/无证/过期），反向用例误判率 > 10% 时回滚。
9. **⭐ 实测验证不可省**（v1.3 新增）：新增场景必须**实际跑一次引擎**确认命中，不只是测试通过率——本案"防护网"场景就发现仅看测试通过率会漏判真实命中。
10. **⭐ 文档同步强制**（v1.5.0 新增·Pitfall 10）：扩展引擎后**必须同步更新三处**——① SKILL.md frontmatter version 号 ② 第二节"引擎逻辑"中"B1-B26 / R-B1-R-B26"规则编号范围 ③ 第三节"引擎能力清单"新增规则表格行 + 第七节"版本记录"追加新版本行。**反例**：v1.4.0 → v1.5.0 实际新增 B25/B26，但三处文档全部未更新，导致下游 agent 凭印象写"B1-B23"误判规则覆盖。
11. **⭐ profile 不可达时不擅自绕路**（v1.5.0 新增·Pitfall 11）：本 skill 仅在指定 profile（如 construction-internal）下注册。当用户在 default profile 触发"分析安全事件"时，agent **不得**通过 `python safety_engine.py` 直跑引擎绕过 skill 触发链（违反 profile 隔离纪律）。**正确动作**：① 先 `skill_view()` 确认 skill 在当前 profile 是否可见 ② 不可见时如实告知用户当前 profile 缺该 skill，给出两个选项（A 切到注册 profile 重发；B 用户显式授权直跑引擎并仍按本 skill Stage 1+2+3 纪律输出）③ 等用户明确选择后再执行。**反例**：agent 默认"绕路调脚本"导致 Stage 2 语义复核、模板输出纪律被静默跳过，用户当场纠错"按 skill 要求来"。

9 个 Pitfall 的完整复现 + 修复见 `references/engine-extension-pitfalls.md`。
