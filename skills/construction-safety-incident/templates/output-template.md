# 建筑安全隐患处置·标准输出模板（v1.2·2026-09-14）

> **来源**：本模板基于多次实际会话沉淀，v1.2 在 v1.1 基础上扩展：
> - 新增 **第 0 节：案件阶段标签**（pre/during/post）
> - 新增 **第 2.5 节：场景叠加判定**（复合规则）
> - 新增 **第 5 节：证据封存清单**（每项隐患对应的证据文件名 + 来源 + 时间窗口）
> - 新增 **第 6 节：阶段适配处置建议**（pre/during/post 三态不同动作）
>
> **适用场景**：用户描述工地安全事件/安全隐患并要求分析、处置、出方案时使用。Stage 1 跑 `safety_engine.py` 后，按本模板输出用户可见方案。
>
> **使用约束**（与 SKILL.md 第三节"处置红线"一致）：
> - ❌ **禁止出现规则编号**（如 `[B1]`、`[R-B2]` 等仅作内部溯源，不得对外）
> - ❌ **禁止出现 Phase 标注、自检清单、内部校验过程**
> - ❌ **禁止出现引擎字段**（如 `stage`、`compound_findings`、`COMPOUND_RULES` 等）
> - ✅ 引擎命中的规则在内部归类，但对外用"风险 1 / 风险 2 / 策略 1..."等友好编号
> - ✅ 文书模板名称可对外（《停工令》《整改通知单》等是行业通用名）
> - ✅ 法律依据可对外（《安全生产法》《建设工程安全生产管理条例》等是法规正式简称）

```markdown
## 二点五、场景叠加判定（仅在多风险并发时启用）

> **启用条件**：风险发现 ≥ 2 项，且其中任意 2 项存在**协同放大效应**（如"动火违规 + 消防不到位"、"起重违规 + 高处作业"、"模板未验收 + 浇筑混凝土"、"板房违规 + 宿舍人员密集"）。

### 叠加风险：[协同放大后的风险定性，如"重大火灾风险（系统性管理失职）"]

- **联动基础风险**：[风险1] + [风险2]
- **风险升级**：[原"较大风险" → 现"重大风险" / 原单项违规 → 现系统性管理失职]
- **责任主体扩展**：[从"施工单位（直接）"扩展至"施工单位（直接）+ 监理单位（监督）"，或更高]
- **叠加解释**：[一句话说明为什么这两项并发会触发协同放大，如"动火违规 + 消防不到位 = 火灾事故几乎必然发生"]
- **协同处置要点**：[合并策略中第 1、2 步，避免重复发整改通知单，统一一次发《系统性隐患整改通知单》]

## 四、阶段适配处置建议（v1.2 新增·按案件阶段输出差异化动作）

> **何时启用**：始终启用。根据 Stage 1 `derive_stage()` 的输出（pre/during/post）选择对应分支。

### A. 事前·隐患阶段（stage = pre）

**核心动作**：监理签发《安全隐患整改通知单》+ 施工单位提交整改方案 + 整改完成经监理验收后复工

**避免误操作**：
- ❌ 不必升级为《停工令》（尚未施工/未到紧迫程度）
- ❌ 不必启动事故应急预案
- ❌ 不必联动三问评估法（尚未发生事故）

### B. 事中·违规进行中（stage = during）

**核心动作**：监理立即签发《停工令》+ 现场封存违规设备 + 施工单位清退违规人员/整改 → 验收后复工

**避免误操作**：
- ❌ 不得以"已经在做了"为由放任继续施工
- ❌ 必须立即停工（不是"先停部分"）
- ❌ 整改完成前不得复工

### C. 事后·已发生事故（stage = post）

**核心动作**：**联动 `rhzy-skill4-incident-duty-allocation` 启动事故责任分配**
- 启动三问评估法（资质审核底档 / 事发前整改记录 / 工程款拖欠）
- 立即上报建设主管部门（按《生产安全事故报告和调查处理条例》时限）
- 现场封存证据（影像/设备/日志/监理记录）
- 配合事故调查组取证

**避免误操作**：
- ❌ 不得瞒报、迟报、隐匿（强制纪律）
- ❌ 不得擅自与受害者家属私了（须经法务审核）
- ❌ 不得以内部协议免除法定责任

### D. 阶段未识别（stage = unknown）

**核心动作**：补问用户——当前是"发现隐患未施工"、"正在违规施工"、还是"已经发生事故"？

**避免误操作**：
- ❌ 不得跳过阶段判断直接出方案
- ❌ 不得假设为事前就发整改通知单（万一已发生事故就是延误报告）
```

## 填充规则（Agent 使用本模板时遵循）

### 标题
- "[项目简称]"：从用户输入的项目名取（如"厂房项目"），无项目名则写"工地"
- "[隐患一句话概括]"：用 5~15 字浓缩三项/多项隐患（如"外墙脚手架 + 塔吊无证上岗三项并发隐患"）

### 案件阶段
- pre/during/post 直接来自 `derive_stage()` 输出
- 阶段未识别时写"未识别（请补充：当前是隐患/进行中/已发生事故？）"

### 风险发现
- **数量**：与引擎命中的独立风险条目数一致
- **排序**：重大 → 较大 → 一般；同级内按危险紧迫度
- **等级判定基准**（与引擎 `RULES` 对应，但对外不暴露）：
  - 重大：坍塌、特种作业无证、深基坑无方案、动火违规+消防不到位、模板未验收即浇筑、高处坠落 ≥5m、有限空间违规、起重吊装违规等
  - 较大：临边防护缺失、临时用电不规范、移动平台未验收、卸料平台超载、施工机械无防护、安全帽未佩戴等
  - 一般：文明施工措施不到位（围挡破损/扬尘超标等）
- **判定依据**：引用案情原文中的关键事实短语，不超过 30 字

### 处置策略
- **数量**：与风险发现一一对应（每项风险一条策略）
- **步骤**：2~4 步，超 4 步要拆策略
- **文书**：每步必带一个文书名称（《停工令》《整改通知单》《工程联系单》《责任切割协议》《复工确认书》等）；同一文书重复出现时合并到一步
- **时效**：按风险紧迫度选"立即执行 / 24h 内 / 48-72h 内"

### 场景叠加判定（v1.2 新增）
- **何时启用**：风险发现 ≥ 2 项且存在协同放大效应时
- **联动基础风险**：列出来自"一、风险发现"中的哪几项
- **风险升级**：明示从原等级升级到什么等级
- **责任主体扩展**：明示从单一主体扩展到什么范围
- **协同处置要点**：合并策略步骤、避免重复发整改通知单

### 处置红线
- 固定 5 条，措辞按 SKILL.md 第四节原文（已写死在上文"红线清单"里）
- 严禁删减或改写核心意思

### 阶段适配处置建议（v1.2 新增）
- 4 个分支（pre/during/post/unknown），每个分支含"核心动作 + 避免误操作"
- 严格按引擎 `derive_stage()` 输出选分支，不要凭感觉判断

### 证据封存清单（v1.2 新增）
- **每项风险对应一个证据表**（含 4 列：名称/来源/固化时点/责任人）
- 每张表至少 3 条证据
- 影像证据必须含时间戳要求
- 书面证据必须含签收回执要求
- 时效红线：事故发生后 24h 内固化全部证据

### 第六部分
- **触发条件**：用户输入信息不足以精准定级（如未提供高度、未说书面指令状态、未说是否发生事故等）时启用
- **问题数**：2~4 个，使用 `clarify` 工具
- **每个问题必须提供 ≤4 个预选选项**，推荐项放第一位

## 反例（不要这样输出）

### ❌ 反例 1：暴露内部规则编号
```
### [B1] 高空作业 + 无临边防护 → 高处坠落风险
- 处理空间：可降级（R-B1 策略）
```
**正确**：
```
### 1. 高空作业 + 无临边防护
- 可降级空间：✅ 可降级 —— 督促立即安装临边防护/停工整改即可降低坠落概率
```

### ❌ 反例 2：暴露 Phase 标注和自检过程
```
[Phase 1] 场景判断完成
[SC-8] 联动 skill 校验通过
进入 Phase 2 输出...
```
**正确**：直接进入"一、风险发现"，不写任何阶段标注。

### ❌ 反例 3：暴露引擎字段
```
stage: pre
compound_findings: [{id: C3, ...}]
```
**正确**：写成"案件阶段：事前·隐患阶段"，不暴露 JSON 字段。

### ❌ 反例 4：给出"通用建议"而非针对性策略
```
1. 应当加强安全管理
2. 应当完善制度
```
**正确**：
```
1. 要求监理单位发出《安全隐患整改通知单》，要求立即停工整改，并留存监理签字记录
2. 在《工程联系单》中明确：高处作业安全防护由施工单位负责...
```

### ❌ 反例 5：隐瞒关键判定依据
```
- 等级：重大风险
```
**正确**：
```
- 等级：重大风险
- 判定依据：原文同时命中"塔吊作业"+"无证上岗"
```

### ❌ 反例 6：跳过阶段适配（v1.2 新增反例）
```
[任何 stage 都用同一套模板]
```
**正确**：post 阶段必须联动 `rhzy-skill4-incident-duty-allocation` + 启动事故上报；during 阶段必须《停工令》；pre 阶段可用《整改通知单》。

### ❌ 反例 7：证据封存清单流于形式（v1.2 新增反例）

```
### 证据 1：
- 监理日志

```
