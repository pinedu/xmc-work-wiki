# rhzy 涉法引用强制纪律（rhzy-law-citation-strict）· v1.3

## 📌 这是什么

一个**类级别**守门 skill，不解决具体业务问题，专管"凡涉法内容必须怎么引才算合格"。所有 rhzy-* skill 在回答里提到以下任意一项时，**必须**先过本 skill 的 4 件套门控：

- 法律 / 法规 / 法条 / 条文 / 条款编号
- 法定年限 / 缺陷责任期 / 保修期
- 罚款金额 / 资质处罚 / 罚则金额区间
- 强制性规范 / 行政许可前置条件
- 政府文件编号 / 国务院令 / 主席令 / 部委令
- ⭐ **v1.1 新增**：国标条文 + 省标条文**二选一判断**（特别是实名制 / 劳动合同 / 工资 / 维权告示牌等）

**立场**：老板原话（2026-07-13）—— "对于涉及法律法规，你需要给出具体的法律条纹款项"。这一条已被这条 skill 永久化，下个会话开机就生效。

## 🚪 4 件套门控（过门才能输出）+ ⭐ v1.1 双轨判断

**任何涉法内容输出，必须同时满足**：

### 门控 1：条款编号（精确到条/款/项）

```
✅ 正确：「国务院令第 724 号《保障农民工工资支付条例》第 24 条」
✅ 正确：「黔人社发〔2022〕18 号 第 13 条第 2 款」
✅ 正确：「消防法第 9-13 条」
✅ 正确：「建市〔2022〕59 号 修订第 8 条」
❌ 错误：「好像是哪个条例」「应该是 26 条附近」「记得有个年限」
❌ 错误：「按国家相关规定」（泛指 = 拒绝接受）
```

### 门控 2：原文（不缩写 / 不意译 / 不拼接）

```
✅ 正确：> 第二十四条 建设单位应当...人工费用拨付周期...【原文整段引用】
✅ 正确：> 第 13 条第 2 款 总承包单位应当...【原文】
✅ 正确：> 将第八条修改为：「...」【建市〔2022〕59 号原文修订引文】
❌ 错误：「建设单位每月拨付」（即没有原文 = 训练数据推测）
❌ 错误：「按当地规定」（伪精确，无原文支撑）
```

### 门控 3：文件名（含文号）

```
✅ 正确：「《保障农民工工资支付条例》（国务院令第 724 号）」
✅ 正确：「《贵州省工程建设领域农民工实名制管理暂行办法》（黔人社发〔2022〕18 号）」
✅ 正确：「《建筑工人实名制管理办法（试行）》（建市〔2019〕18 号，建市〔2022〕59 号修订）」
❌ 错误：「某个国务院令」（不写编号）
❌ 错误：「某省某文件」（不写文号）
```

### 门控 4：落档 URL（wiki 本机路径 + OSS HTTPS + 锚点）

```
✅ 正确：4 层标识（业务 ID + 本机路径 + OSS URL + 锚点）
❌ 错误：只给本机路径（异地失效）
❌ 错误：只给印象（无任何 URL）
```

完整 4 层标识规范见 `rhzy-citation-linker-toolkit` / `rhzy-skill10-citation-linker`。

### ⭐ 门控 5（v1.1 新增）：国标 vs 省标·双轨判断

> **rhzy 项目实务判断铁律**：贵州境内项目，**省标严于国标时，按省标**；国标与省标一致时直接执行。

**触发场景**：
- 实名制入场资格（劳动合同 vs 用工书面协议）
- 维权告示牌规格
- 数据保存年限
- 劳资专管员配置
- 项目登记时限
- 工资保证金减免条件

**判断步骤**：

1. 先到 `gz-construction-law-wiki::references/wage-law-supplement-2026-07-13.md` 看对照表
2. 比对国标条款 + 省标条款的差异点
3. 业务结论 = **「贵州境内项目按省标；外省项目按国标」**
4. 引用输出必须含「国标第 X 条 / 省标第 X 条」**双条款**

**反例（v1.1 之前踩过的坑）**：
- ❌ 只引用国标"劳动合同或用工书面协议" → 忽略了贵州省标仍要求订立劳动合同
- ❌ 只引用贵州省标 → 没标注国标口径修订
- ❌ 笼统说"按国家或地方规定"——强制拒绝

**正例**：
- ✅ 国标第 8 条修订后「劳动合同或用工书面协议」+ 贵州省标第 14 条「订立劳动合同并进行用工实名登记」+ 业务结论「贵州境内项目默认走劳动合同，无法建立劳动关系才用书面协议」

## ⚠️ 典型失守模式 + Pitfall

### Pitfall 1：训练数据补条款编号（最常见）

**反例**："按《建设工程质量管理条例》第 40 条规定，主体结构保修期 5 年"

- 本机 wiki **未落档**这部法规
- 没有原文档案
- 出现 "5 年" / "40 条" 等具体数字 = **违反了"无原文 = ⚠️ 待查证"原则**

**正确**：不写条款编号、不写具体年限 → 改为「⚠️ 待补：本机未落档《建设工程质量管理条例》（国务院令 279 号）。待用户提供 docx 后落档再引」

### Pitfall 2：拼接不同文档片段生成看似合理的条款

**反例**：从一部法规摘出"建设单位负总责"+ 从另一部摘出"必须招标"+ 从训练数据补"具体年限" = **捏造了一部不存在的法规条款**

**正确**：要么给完整原文 + 源位置，要么 ⚠️ 不给

### Pitfall 3：泛指条款却带具体数字

**反例**："按相关规定须缴存 5% 工资保证金"——"相关规定"是泛指，"5%" 是具体数字 → **无原文支撑的具体数字 = 不接受**

**正确**：「⚠️ 待补：本机未落档相关规定，待用户确认比例」

### ⭐ Pitfall 4（v1.1 新增）：国标 vs 省标·遗漏省标更严的红线

**反例**（2026-07-13 真实场景）：
- 老板问"临时工入场要不要签劳动合同？"
- AI 只引国标第 8 条修订"先签劳动合同或书面协议"
- 漏了贵州省标第 14 条"订立劳动合同并进行用工实名登记"
- **结论错了**：让老板以为临时工可以靠"书面协议"绕过劳动合同——**但贵州境内项目不可**

**正确**：
1. 国标第 8 条 + 贵州省标第 14 条**双轨引用**
2. 业务结论明示「贵州境内项目必订立劳动合同」
3. ⚠️ 标明「国标 vs 省标双轨判断已加载 gz-construction-law-wiki::references/wage-law-supplement-2026-07-13.md 对照表」

### ⭐ Pitfall 5（v1.1 新增）：双存版本引用冲突

**反例**：
- 同时引用 `~/wiki/concepts/上位法/保障农民工工资支付条例.md`（摘要）和 `~/wiki/concepts/实名制管理汇编/保障农民工工资支付条例_全文.md`（全文）
- 让老板选——老板会问"以哪个为准？"

**正确**：
- 优先全文版
- 引用时只引**一条**，并在 4 层标识里写明版本（如 `rhzy-upperlaw-农民工工资支付条例-fulltext`）
- 如必须双引（如对比摘要版 vs 全文版新增条款），明示「双存」标签

### ⭐ Pitfall 6（v1.2 新增·2026-07-13 老板纠错沉淀）：⚠️ 与"已落档"不得共线

> **老板原话**（2026-07-13 履约考核节点）：
> > "⚠️ 上位法：《土地管理法》（主席令第 32 号）—— 已落档全文版，这个法律文件不是已经落档了吗刚刚"

**反例（2026-07-13 本会话真实踩坑）**：

我在"罗列贵州省建设单位开工前职能"回答中连续写了 5 处：
- A3 ⚠️ **《土地管理法》（主席令第 32 号）—— 已落档全文版**
- A4 ⚠️ **《环境保护法》（主席令第 9 号）—— 已落档全文版**
- B4 ⚠️ **《消防法》（2019 修正）—— 已落档全文版**
- C7 ⚠️ **《建筑工程施工许可管理办法》（住建部令 18 号）—— 已落档**
- C12/D2 ⚠️ **《建设工程质量管理条例》（82 条）—— 已落档**

每行 ⚠️ 图标和"已落档"两个**相互矛盾**的状态放在同一行。

**老板一眼看出**：要么没落档要么落档了——**两边都对得上**—— ⚠️ 是"未落档"标记，"已落档"是"生效中"确认，两个图标并排 = **触发矛盾信号**。

**根因**：
1. ⚠️ 我之前把它**当作通用警示图标**用（任何"注意"都标），没限定它就是"未落档"的唯一标识
2. 没有在写 ⚠️ 之前**先 probe 本机档案**——这是核心失误
3. **半手动半自动**——我脑子里有"上次落档的印象"，但行文中又用 ⚠️ 表达"待补"——认知不一致

**正确做法（v1.2 铁律）**：

1. **三元法**：`✅`（已落档可引）/ `⚠️`（未落档待补）/ `❓`（信息不全待问）—— **三选一**，不分场合再用 ⚠️ 表达其它意思
2. **写 ⚠️ 前必须 probe**：
   ```bash
   ls -la ~/wiki/concepts/上位法/中华人民共和国土地管理法_全文.md
   grep -E "主席令第32号" ~/wiki/concepts/上位法/中华人民共和国土地管理法_全文.md | head -3
   ```
3. **probe 结果 4 个分支**：
   | probe 结果 | 应该标 | 后续动作 |
   |---|---|---|
   | 文件存在 + 关键字命中 | ✅ 已落档 + 4 层标识 | 直接引用 |
   | 文件存在 + 关键字不命中 | ⚠️ 已落档但待核对条文版本 | 标 ⚠️ + 解释"汇编版本可能与最新版错位" |
   | 文件不存在 | ⚠️ 待补档 | 标 ⚠️ + 列"老板需补哪些文件" |
   | 信息不全 | ❓ 需补充 | 标 ❓ + 问老板 |
4. **同一行只一个状态符**：✅ + 已落档 / ⚠️ + 待补档 / ❓ + 需补充——**绝不共线**

**反例必须消除**：
- ❌ "⚠️ 已落档" → 自相矛盾
- ❌ "⚠️ 待补 + 已落档" → 双重矛盾
- ❌ "⚠️ 待核对 + 已落档" → 双重矛盾
- ✅ 改为："✅ 已落档（82 条 / 27,139 字节）但汇编版本与 2019 修订可能错位"

**强制输出自检 Checklist**（v1.2）：每次发涉法回答前跑这 3 步：
1. grep 一次所有 ⚠️ 行——是否出现"已落档 / 已建档 / 已补档"等确认词？
2. 出现则**逐行**回到 probe 重新核对
3. probe 不出来的，**改用 ❓ 状态符**——不要让 ⚠️ 既是"未落档"又是"待核对"

### ⭐ Pitfall 7（v1.2 新增·2026-07-13 沉淀）：4 次重复 docx 落档也按 5 步 SOP 跑

> **老板原话**（4 次"对该文件内的法律文本进行落档"）：
> 真实频次：实名制汇编 ×2 + 贵州省地方法律法规 ×1 + 国家级上位法汇编 ×1

**反例**：
- 老板第 N 次发"落档"指令，我每次都从零开始——
- 不复用已沉淀的 `references/drop_docx_sop.md` + `scripts/drop_laws_template.py`
- 不 md5 比对——同 docx 重复发时启动全新流水线

**正确做法**：
1. **每次"落档"指令先 md5 比对**——同名 docx hash 一致 = 复用
2. **加载 `gz-construction-law-wiki::references/drop_docx_sop.md`** —— 5 步流水线已固化
3. **脚本复用**：直接复制 `scripts/drop_laws_template.py` 改 3 个变量（SRC / DST_DIR / LAWS）
4. **不向老板要 A/B/C 决策**——落档 = 直路
5. **不能解析时**（如 docx 是扫描件无 OCR）才向老板请示

详见 `gz-construction-law-wiki::references/drop_docx_sop.md` 第 4 步"双存命名规则" + `references/27-部法律档案实证清单.md`（v3.0 新增）。

### ⭐ Pitfall 8（v1.3 新增·2026-07-13 沉淀）：rhzy-functional-coverage-audit 触发涉法回答时"skill 失忆"——必须显式加载本 skill

> **老板原话**（2026-07-13 测试点 5 后的追问）："你提到了《建设工程质量管理条例》第 40 条，但没有写出原文。请补充原文。"

**反例（2026-07-13 本会话真实踩坑）**：

老板在 `rhzy-functional-coverage-audit` 测试中问"项目交付后屋面漏水，建设单位该不该派人修"。

我**本应只判定"超出建设期硬边界 → 移交运营 → 不派人修"**——但我**外推了 5 条理由**：

> ❶ 业主投诉到住建局，**需要质量保修依据**——我"凭印象"写了"按《建设工程质量管理条例》第 40 条，屋面防水 5 年保修期"
> ❷ 第 41 条保修责任
> ❸ 第 19 条勘察设计责任
> ❹ 第 20 条勘察成果真实
> ❺ 第 21 条设计必须根据勘察成果

老板立即纠错："你提到了《建设工程质量管理条例》第40条，但没有写出原文。请补充原文。"

**根因**：
1. **我**输出了"5 年保修期"等具体数字 + 条款编号——**Pitfall 1 失守**
2. **rhzy-functional-coverage-audit 是判定类 skill，不是涉法 skill**——但它在判定中"夹带"了涉法内容
3. **我**没有**在判定时显式加载本 skill `rhzy-law-citation-strict` 过 4 件套门**——这就是"skill 失忆"
4. **本机 wiki 已落档《建设工程质量管理条例》（80+ 条 / 国务院令第 279 号）**——但我**根本没用**，凭印象写

**正确做法（v1.3 铁律）**：

1. **任何 rhzy-* skill 在回答中提到"第 X 条" / "X 年" / "罚款 X 万"等具体内容** → **必须立即加载本 skill 守门**（即使主 skill 不是涉法 skill）
2. **本机已落档的法规**（`gz-construction-law-wiki` 中收录的 32 部落档）→ 必查 + 引用原文 + 4 层标识
3. **本机未落档的法规** → 标 ⚠️ 待补 + 列出"老板需补 docx"
4. **rhzy-functional-coverage-audit 调用本 skill 的时机**：
   - 判定"白名单外"涉及**法务/合同/法规** → 必加载
   - 判定中给出"理由"涉及**条款编号** → 必加载
   - 模拟环境 3 段式中"❌ 不能确定"提到"原文未挂载" → 必加载

**强制输出自检 Checklist**（v1.3）：

**反例必须消除**：

## 📋 工作步骤（每次涉法回答必跑）

1. **检测触发条件**——回答里是否出现"法""条例""规定""条款""年限""罚款""第 X 条"等关键词
2. **选定法规**——本机 `~/wiki/concepts/` + `~/wiki/concepts/实名制管理汇编/` 是否有已落档档案
3. **⭐ v1.1 增补**：是否涉及国标 vs 省标差异？→ 加载 `gz-construction-law-wiki::references/wage-law-supplement-2026-07-13.md`
4. **⭐ v1.3 增补**：rhzy-functional-coverage-audit 触发的判定回答 → 必加载本 skill
5. **查 5 件套**——条款编号、原文、文件名、URL、双轨判断齐全吗？
6. **如缺**：立即打 ⚠️ 待查证 → 列出"老板需要补哪些文件"
7. **如齐**：按规定格式输出（飞书友好：emoji + 加粗 + `>` 引用块，不用 ASCII 表）

### 输出模板（v1.3 升级·涉法 + 双轨 + 落档 4 层标识）

```markdown
**🔗 [法规名]（文号）** [若与国标有差异：⭐省标 / ⭐国标]

> 【原文块——保留原文格式，必要时分段】

📌 **本机落档位置**：4 层标识
  - 业务 ID：...
  - 本机路径：...
  - OSS URL：...
  - 锚点：#第X条

⭐ **双轨判断**（如涉及国标 vs 省标差异）：
  - 国标第 X 条：[原文]
  - 贵州省标第 X 条：[原文]
  - 业务结论：[贵州境内项目按省标 / 外省项目按国标 / 一致直接执行]

⚠️ 待补档案（如有）：逐部列出
```
