# 供应商开票信息核验 SOP（v1.0 · 2026-09-03 沉淀）

> ⚠️ **本 skill 解决的事**：开票信息 ≠ 合同主体资格。一份"开票资料"只回答"钱付给谁、票开成谁"，**不回答**"这家能不能承接这份合同"。两份事必须分开看，混在一起 = 付款后扯皮。

## 一、触发场景

老板丢任何形式的开票信息进来（docx / pdf / 截图 / 微信文字 / 邮件），明确表达以下任一意图时触发本 skill：

- "入档" / "登记" / "建个供应商档案"
- "付款前复核一下" / "这家能不能付"
- "合同要签了，先看看" / "主体够不够格"
- "开票信息整理一下" / 单纯要求结构化沉淀

老板只发开票信息没说意图 → **默认走"标准核验 + 入档"流程**，不主动判定"能不能付款"。

## 二、标准流程（5 步）

### 步骤 1：4 字段提取

不论输入格式如何，统一抽成 4 字段：

```
单位名称：
税号（统一社会信用代码）：
地址、电话：
开户行及账号：
```

⚠️ **字段缺失处理**：

- 单位名称缺失 → 必须要求补全，无名称不可入档
- 税号缺失 → 必须要求补全，无税号不可入档（无法开票也无法核验）
- 地址电话任一缺失 → 标"⚠️ 待补"，**可入档但付款前必须补齐**
- 开户行及账号任一缺失 → 必须要求补全，无账号不可入档（无法付款）

### 步骤 2：税号格式校验（GB 32100-2015）

统一社会信用代码 = 18 位 = 登记管理部门代码（1 位）+ 机构类别代码（1 位）+ 登记管理机关行政区划码（6 位）+ 主体标识码（9 位）+ 校验码（1 位）。

**校验规则**：

| 位次 | 含义 | 取值范围 |
|---|---|---|
| 1 | 登记管理部门 | 1=机构编制 / 5=民政 / 9=工商 / Y=其他 / A=工会 / N=农业 / 其他 |
| 2 | 机构类别 | 数字或大写字母 |
| 3-8 | 行政区划 | 6 位数字 |
| 9-17 | 主体标识码 | 9 位数字 |
| 18 | 校验码 | 大写字母或数字（按 ISO 7064:1983 MOD 31-3 计算） |

**快查规则**（老板拍板用，不必手算校验码）：

- 第 1 位 = 9 → 工商注册企业（最常见）
- 第 1 位 = 5 → 民政注册（社团/民非）
- 第 1 位 = Y → 其他
- 第 2 位 + 第 1 位组合 → 查《法人和其他组织统一社会信用代码编码规则》附录
- 长度 ≠ 18 位 → **格式不合规，直接判黄**

⚠️ **判定结论必须分 3 档**：

- ✅ 格式合规 + 18 位 + 字符集合法
- ⚠️ 格式合规但缺位（如 15 位老税号）→ 标"⚠️ 老证换新未完成"
- 🔴 格式不合规 → 不可入档

### 步骤 3：经营范围匹配

⚠️ **核心铁律**：开票信息里**没有**经营资质信息——公司名里写的"数据服务"/"咨询"/"工程"等字样**不等于**营业执照经营范围内的对应类目。

**老板必须自己提供的 2 个信息**：

1. 本次合同/业务的实际内容（"工程咨询" / "造价审计" / "法律服务" / "数据处理" / "软件开发" / "设备采购" / "材料采购" / 其他）
2. 对应的营业执照经营范围（**必须看原件截图**，不能只看公司名猜）

⚠️ **本 skill 不替老板判定"经营范围够不够"**——这要查原件 + 看合同 + 必要时走法务（联动 `rhzy-skill2-legal-counsel`）。本 skill 只做"是否需要老板提供这两项"的提醒。

### 步骤 4：信用核验清单（付款前必跑）

不论老板是否要求付款，**任何开票信息入档后必须给一份付款前 checklist**：

```
【付款前必查 · 5 件】
1. 国家企业信用信息公示系统（gsxt.gov.cn）：查"是否存续/经营异常/严重违法/法人变更"
2. 中国执行信息公开网（zxgk.court.gov.cn）：查法人+公司是否"失信被执行人"
3. 国家税务总局重大税收违法案件公布栏：查"重大税收违法"
4. 中国裁判文书网（wenshu.court.gov.cn）：查近 1 年案件（劳动争议集中 = 拖欠工资风险）
5. 人民银行征信（如可查）：法人/股东征信

⚠️ 任意一项命中 = 立即暂停付款 + 老板拍板
```

5 件全过 + 老板签字确认 → 才能走付款流程。

### 步骤 5：输出核验报告 + 入档

输出模板（老板拍板用，1 屏能看完）：

```
【开票信息核验报告】v1.0

▎ 供应商：<单位名称>
▎ 税号：<18 位统一社会信用代码>
▎ 状态：✅ 入档 / ⚠️ 待补 / 🔴 拒收

▎ 字段完整性：4/4 / 3/4 / 2/4 ...
▎ 税号校验：✅ / ⚠️ / 🔴
▎ 经营范围匹配：⚠️ 需老板提供合同类型 + 营业执照经营范围原件
▎ 信用核验：⏳ 待跑 / ✅ 全过 / 🔴 命中 X 项

▎ 付款前 checklist：已附 / 待附
▎ 入档日期：<YYYY-MM-DD>
▎ 录入人：<老板 / 小建>

⚠️ 缺失项：<逐条列明>
💡 下一步建议：<具体动作>
```

## 三、首案沉淀（2026-09-03 老板指令）

### 案例 1：贵州人和致远数据服务有限责任公司

**原始输入**：微信发送 docx《开票信息（人和致远）》

**4 字段提取**：

| 字段 | 值 |
|---|---|
| 单位名称 | 贵州人和致远数据服务有限责任公司 |
| 税号 | 9152019033731702XF |
| 地址、电话 | 贵州省贵阳市观山湖区林城西路摩根中心 A 座 8 层 1 号 / 86839689 |
| 开户行及账号 | 建设银行贵阳北京路支行 / 52001617500052504141 |

**税号校验**：

- 第 1 位 = 9（工商注册）✅
- 第 2 位 = 1（企业）✅
- 第 3-8 位 = 520193（贵州省贵阳市）✅
- 总长 18 位 ✅
- **初步结论：✅ 格式合规**

**经营范围匹配**：

- ⚠️ 缺失项 1：合同类型未知（老板未告知）
- ⚠️ 缺失项 2：营业执照经营范围原件未提供
- **本 skill 不替老板判定，需老板补充**

**信用核验**：

- ⏳ 待跑（5 件 checklist 已附）

**项目库对位**：

- 🔴 在云岭中心 / 小关安置房既有合同/分包商白名单中**未出现过** = 新供应商
- **本 skill 提醒**：新供应商首次合作建议老板面谈 + 实地看场地 + 法人到场签字

**入档结论**：⚠️ 待补（经营范围匹配 + 信用核验 5 件）+ ✅ 字段完整 + ✅ 税号格式合规

## 四、与现有 skill 的关系

| 关系类型 | 哪个 skill | 区别 |
|---|---|---|
| 联动 | `rhzy-contractor-due-diligence` | 本 skill 触发后，信用核验 5 件可委托 contractor-due-diligence 跑 6 个公开数据源 |
| 联动 | `rhzy-skill2-legal-counsel` | 经营范围匹配存疑 → 走法律顾问判定"主体资格 + 合同效力" |
| 联动 | `rhzy-functional-coverage-audit` | 本 skill 输出"⚠️ 待补"后，老板问"那这事归谁管" → 走职能覆盖度审计 |
| 不同 | `rhzy-fund-skill1-funding-source-risk` | fund-skill1 看资金来源（权益/债务/财政/供应链）风险；本 skill 看付款对手方风险 |

## 五、反模式档案（老板禁止本 skill 做的 5 件事）

1. ❌ 替老板判定"经营范围够不够"——必须看原件 + 走法律
2. ❌ 替老板拍板"能不能付款"——必须跑信用核验 5 件 + 老板签字
3. ❌ 只看公司名里的"工程/咨询/服务"字样推断经营范围——必须看营业执照
4. ❌ 老税号（15 位）当新税号用——必须要求换 18 位
5. ❌ 入档后不再复核——付款前必须重新核一遍（公司可能在入档后被列入异常）

## 六、老板输出标准格式（3 选 1）

| 老板语气 | 输出 |
|---|---|
| "整理一下" / "入档" | 标准核验报告（5 字段 + 5 步结论） |
| "付款前复核一下" | 核验报告 + 5 件 checklist + ⚠️ 命中项 |
| "合同要签了先看看" | 核验报告 + 经营范围匹配提醒 + 主体资格对位 |

老板没指定语气 → **默认走标准核验报告**，不主动展开支付/合同意见。
