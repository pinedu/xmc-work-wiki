# 月报组装层（项目端 · 全量 Word 生成器 + 双布局适配）

## 一、定位

按标准月报成品《云锦华府二期项目2026年8月数据监理服务月报.html》的结构与措辞，生成可直接交付的 Word 月报。**字段纪律：标题、指标名、字段名、说明措辞一律用该 HTML 标准件的原文，禁止自行改写、简化、替换**（2026-10-12 老哥拍板）。pos 导图《运营报告以及工资计算逻辑.pos》降为逻辑底层，冲突处 HTML 标准件优先。

封面（标准件范式）：标题 = `{项目名}工人工资数据监理服务月报`；信息表九行（项目名称/报告期间/数据截止时间/报告生成单位/建设单位/施工单位/监理单位/报告编号/报送对象）+ 数据来源声明；文末落款（编制/审核/报送 + 报告编号/出具日期）。

联动关系：
- `wage-pay-judge`（判定引擎）：输入当月工资册＋考勤＋花名册＋工种单价表，按 JudgeConfig 策略输出每人"超付/欠付/可能欠付/正常"及金额，并吐出结构化 JSON。
- `month-report-builder`（本技能）：调用引擎 → 读 JSON → 套报告格式 → 写进 docx；其余板块用项目数据现算、图表用 matplotlib 现画。

> 判定逻辑单一来源，绝不重复实现；超付/欠付口径以引擎 + JudgeConfig 为准。

## 三、联动契约（JudgeConfig 策略对象，全参数化）

`judge_config.json` 字段（缺项用默认，默认即标准口径零破坏）：

| 键 | 取值 | 含义 |
|---|---|---|
| `threshold_mode` | `warn`（默认）/ `hard` | 阈值模式：warn=预警值（上限×1.30/下限×0.85）；hard=样例硬区间 |
| `second_round` | `seat`（默认）/ `hold` | 欠付第二轮：seat=拉历史均值坐实；hold=统一维持"可能欠付(待复核)"不坐实 |
| `gongzhong_resolve` | `roster_only`（默认）/ `team_fallback` | 工种缺失处理：roster_only=缺即缺；team_fallback=按班组名反推 |
| `attendance_source` | `kaoqin` / `work_days` | 用工量口径：考勤天数 / 工资表工作天数 |
| `team_gong_map` | `[[关键词, 工种], ...]` | 班组名→工种映射（team_fallback 用） |
| `price` | 路径 | 工种单价表（默认就近 `工种单价预估范围.xlsx`） |

金额公式：
- 超付金额 = Σ(实发 − 上限×1.30×考勤)
- 欠付金额（坐实）= Σ(下限×考勤 − 实发)；`hold` 模式下当期坐实欠付 = 0，仅列"可能欠付待复核"

## 四、引擎 JSON 契约（报告侧消费字段）

```
payload.summary:        total_workers / over / under / possible_under / normal / cannot_compute / missing_gongzhong / over_amount / under_amount
payload.four_category:  attendance_no_salary[] / salary_no_attendance[] / over[] / under[]
payload.persons[]:      逐人判定结果
payload.prior_months:   历史月份列表
payload.attendance_only[]: 仅考勤无工资人员
payload.salary_anchor:  对账锚 {ym, batch_count, batch_sum, detail_count, detail_sum, ok}（2026-10-16 新增；ok=False 时报告 2.5/3.1.2 亮红字、进待补充清单，超欠付数字仅作参考）
```
报告仅消费此结构，不重算判定。

## 五、报告结构（对齐 HTML 标准件《云锦华府二期项目2026年8月数据监理服务月报》）

**字段纪律：所有板块标题、指标名、字段名、说明措辞一律用该标准件原文，禁止自行改写、简化、替换。**

- **封面**：标题 `{项目名}工人工资数据监理服务月报`；信息表九行（项目名称/报告期间/数据截止时间/报告生成单位/建设单位/施工单位/监理单位/报告编号/报送对象）+ 数据来源声明；文末落款（编制/审核/报送 + 报告编号/出具日期）。
- **一、项目概况**：项目名称、项目类别/适用拨付比例、建设单位（现场负责人）、施工单位（项目经理/劳资专管员）、实际开工/预计完工、项目已运行/预计剩余（自然月）、当前形象进度、薪莫愁数据监理服务介入时间（第一次扫码登记入库时间）+ 责任划断声明（介入前仅作梳理不对真实性合规性负责，介入后按标准流程核查并负责）。
- **二、项目健康度分析**：2.1 健康度汇总表（五项指标）：①-⑤ 带序号 + 综合评级行（拨付率入综合评级说明）；判定口径：六项全合格=合格/有黄=提示/有红=警告。2.2 六项制度落实情况：工资保证金存储/劳动合同签署/实名制打卡/人工费分账拨付/工资银行代发/离场结算；状态词=达标/限期整改/严重违规/待平台回填；图=横向圆角色条（绿达标/黄限期整改/红严重违规）。2.3 项目欠薪投诉情况（三端口）：统计维度表（历史累计/其中政府端/项目端/薪莫愁端/本月新增/已解决/未解决 × 投诉件数+涉及金额）+ 走势图（柱=三端口合计、三线=各端口，数据走 meta.complaints）+ 文字分析。2.4 项目资金情况：八行表（累计报审产值/累计审定产值/建设单位累计拨付工程款+拨款进度率/专户累计进账/合规分账进账/分账拨付率/专户累计发放工资/专户剩余资金）+ 资金拨付图 + 拨付率走势图（带政策线 20%）。2.5 本年度工资发放统计（截至报告期）：年度表（月份/实发工资万元/发放人数/考勤总天数/备注，含本年累计行）+ 双轴图 + 当月工资整体审核情况段（应发/实发/发放率 + 四类异常）。
- **三、工资审核**：3.1 主要审核点（审核依据段：行情单价为准、不采用合同单价、合同价仅在 3.2.2 作偏离度校验；预警区间 = [行情下限×(1−15%)，行情上限×(1+30%)]）；3.1.1 日工资离散分析（散点图：x=考勤天数 y=日工资，区间内蓝/超上限黄/低于下限红 + 双参考线 + 双峰文字分析）；3.1.2 超欠付预警清单（四行汇总表：类型/人数/金额/分布与说明 + 全年追溯结果）；3.1.3 次月预估工资（在册人数/考勤天数/预估公式/加权平均日工资/专户剩余/资金缺口）；3.1.4 全年日工资水平分布（柱状图 1 张，0-87/88-200/201-300/301-400/401-500/>500 分档 + 文字分析）；3.2 次要审核点（3.2.1 线下考勤与黔薪保考勤比对：班组/人数/两边考勤/差异表，差异超3天提示；3.2.2 进场合同抽查：新进场/抽查/不合规 + 低工价合同偏离度提示；3.2.3 离场结算抽查：离场/抽查/不合规 + 超30日未结算红色风险）。
- **四、人员情况**：4.1 当月用工情况（班组/用工人数/考勤天数/人均考勤表+合计行 + 班组水平条图 + 班组考勤折线图 + 用工变化分析）。
- **五、其他特殊情况**：5.1 欠薪事件处理（历史累计/已解决/未解决 × 人数+金额表 + 处置说明）；5.2 迎检情况（次数 + 详情；有就写无就不写）。
- **六、建议与反馈**：6.1 对建设单位的建议 / 6.2 对施工单位的建议（数据驱动：分账缺口、专户覆盖、四类异常自动生成要点）/ 6.3 五级反馈机制启动情况（劳资员→项目经理→建设单位现场负责人→建设单位集团负责人→行管部门；仅存在问题未整改时启动）。

## 六、数据可算性 / 待补充数据规则（2026-10-12 老哥定的规则）

**规则：凡本次未能拉取到的数据，一律落【待填】就地占位，并在报告末尾（落款后）汇总成《附：待补充数据清单》——序号/所属板块/待补充数据项/补充途径四列，按板块顺序归组；全部补全后附录自动消失（零待填不输出）。**

补充途径口径：qxb 源标注平台工具/接口未回填（如"系统接口 complaint_ledger（投诉台账）未配置或无数据"，映射表 `_PENDING_HINTS` 可扩）；附件扫描兜底仍取不到时标注"附件扫描亦未取到"。
**⚠️ "0"与"待填"语义区分（2026-10-16 老哥拍板）**：接口正常返回 0 条 = **确认无数据，显示 0**（如投诉台账 0 条 → 三端口表全部显示 0 件 0 万元，并注明"平台台账 0 条"）；只有**接口故障/无权限/无对应工具**才落【待填】。datasource 侧以 `None`（故障）与 `[]`（确认 0 条）区分返回值。

**可自动算**：劳动合同签约率、已运行月数（需人工提供薪莫愁介入时间）、工资发放金额/人数/考勤天数、各班组用工与考勤、全年日工资分布、超付欠付（引擎）、次月预估（价格均值×考勤）、加权平均日工资、资金缺口、拨款进度率、分账拨付缺口、当月应发/实发人数与发放率、六章数据驱动建议。

**人工填报字段（2026-10-16 老哥拍板）**：薪莫愁介入时间——**不从花名册最早入职反推**（最早入职≠服务介入时间，语义不同），一律走 meta/附件提取提供，缺省【待填】。

**【待填】**（就地占位+进末尾清单；qxb 源经 MCP 工具与 `project_meta()` 回填，**键=占位标签名**）：封面类（数据截止时间/监理单位/报告编号/报送对象/出具日期）、概况类（项目类别/现场负责人/项目经理/劳资专管员/当前形象进度/预计剩余时间）、汇总表（已解决欠薪占比/非建设单位打款情况/专户够发判定/分账拨付率）、六项（保证金状态/分账拨付状态/离场结算状态）、3.2（合同抽查份数、低工价合同提示、离场结算抽查份数、超30日未结算离场、线下考勤对比文字）、五章（欠薪事件处置说明）、六章（五级反馈启动情况）。结构化数据（complaints/fund_flow/output_value/offline_attendance/complaint_ledger/six_indicator_status/inspections/entry_exit/next_attendance/yearly_salary）无数据时对应图表/表格降级占位，不崩。

> 注：当花名册**无进退场状态列**（如中医药）时，"在岗/离场人数"自动降级为【待填】，不显示误导性的 0。

## 七、数据源适配器（唯一外部数据源：qxb）

**数据源政策（2026-10-13 老哥拍板）：外部数据源只保留 qxb（黔薪保平台 MCP）**。
standard/zhongyi 文件源、db HTTP 接口源、custom 自定义适配器已全部从 skill 移除
（`datasource_db.py`/`datasource_template.py` 已删除，`make_datasource` 仅接受 `qxb`/`mcp`）；

### ⚠️ qxb MCP 串行调用铁律（消费侧同样遵守，2026-10-16 老哥拍板）

本生成器通过 `QxbMcpDataSource`（`wage-pay-judge/scripts/datasource_qxb.py`）从黔薪保平台取数，**严禁并发调用**——必须**串行**，每次调用间隔 **5 秒**（2026-10-19 由 3 秒上调）。否则触发平台风控（限流 / 封 IP / 拒绝服务），所有取数拉空。

- **职责分工**：本技能不直接调 MCP——串行约束已下沉到 `datasource_qxb.py` 的 `_McpHttp.call()` 入口（单进程天然串行），消费侧无需重复处理
- **影响**：单次月报生成耗时会显著拉长（每次 MCP 调用 +5 秒），但项目/ skill/第三方数据完整性优先
- **调试 agent 直探 MCP 时同样遵守**（见 `~/.workbuddy/MEMORY.md` 通用守则）

## 八、运行方式

统一生成器（唯一数据源）：
```bash
# 黔薪保平台 MCP（连接复用 WorkBuddy mcp.json 的 qxb server；project_id 运行时从当前账号解析）
python build_full_report.py --target 26.8 --data "<含工种单价表的目录>" \
    --source qxb --judge-config judge_config.sample.json [--out xxx.docx]
# 多项目账号加 --project-name <项目名>；附件扫描提取结果用 --attach-data <提取.json> 内联传入
```

**⚠️ 极速模式（2026-10-22 老哥拍板，默认开启）**：月报默认走极速模式（原"快速模式"），**启动命令无需再带 `QXB_FAST_MODE=1`**——仅显式设 `QXB_FAST_MODE=0` 才走全量历史模式。极速模式行为：考勤只拉报告年 1 月~报告月（2.5 年度天数列 + 3.1.4 全年分布所需），报告年之前月份不拉；自动开磁盘缓存。**单缓存文件（2026-10-23 老哥拍板）**：缓存为 `<data>/qxb_cache/qxb_cache.json` 一个文件（跟项目走、不跟报告月走），含工资全量/花名册/逐月考勤（kaoqin 以月为键）；数据源写盘为临时文件+原子替换，杜绝半截 JSON。生成某月月报只补拉缺失月份，历史数据全吃缓存。首次升级时若目录里还有旧的按月缓存（qxb_cache_YYYYMM.json），自动合并迁移进单文件后改名 .bak 退役。**欠付第二轮必须跑**：引擎历史窗口默认=报告年 1 月~报告月前（当年口径，如 26.7 → 最近 6 个月）——历史日薪只算当年、跨年不算（2026-10-22 老哥拍板，任何模式一致，原"历史窗口=0"的口径作废）；显式传 `--history` 可覆盖。其他环境变量：`QXB_CALL_INTERVAL` 覆盖串行间隔（默认 5 秒）。

**考勤矩阵限流/验证码退避（2026-10-22 老哥拍板）**：attend_table 触发"当前接口达到限制次数，请稍后再试"或验证码时，隔 2 分钟再试探一次（单分包上限 5 次≈10 分钟；试探 5 次仍失败即回退打卡流水，流水果断切、不硬磨）。两次退避之间的瞬时失败（读超时等）独立计 5 次额度，退避后清零重计。矩阵优先，但回退要快。

参数：`--target`（报告月，与平台 payMonth 约定一致，必填）、`--data`（仅用于定位本地工种单价表，可指向任意目录；找不到回退 references 的 md）、`--engine`（默认指向上级 judge.py）、`--source`（qxb|mcp，默认 qxb）、`--judge-config`（判定策略 json，**仅判定口径、不含 project_id**）、`--project-id`（32 位项目 ID，覆盖运行时解析；或设环境变量 `QXB_PROJECT_ID`）、`--project-name`（qxb 项目名，运行时从当前账号匹配解析 project_id；单项目可省略）、`--attach-data`（附件扫描提取结果 JSON，agent 读图后内联传入，不落项目目录）、`--history`（all 或 N；默认=报告年当年窗口，见上方极速模式段）、`--offline-att`（**3.2.1 线下考勤册 xlsx，2026-10-23 新增**：月度工资册本身即线下考勤册，"工作天数"列=线下出勤；按人名关联黔薪保当月考勤、班组名归一后比对，差异≥3天/无平台考勤/平台有考勤线下册无三类结果自动写入 3.2.1；有此参数时 3.2.1 不再标【待填】）、`--out`（默认 `<data>/数据监理月报_<target>.docx`）。
**缓存位置（2026-10-22 起不再绑定快速模式）**：磁盘缓存无条件默认落 `<data>/qxb_cache/qxb_cache_<ym>.json`（工作空间，随项目盘——原 Temp 路径会被系统清理且有 C 盘空间压力）；缓存含全部工资明细/花名册/逐月考勤/判定依据，**属项目数据，不得随 skill 分发**。也可用环境变量 `QXB_CACHE_FILE` 显式覆盖。
**注意**：`--judge-config` 传相对路径时引擎子进程按调用方工作目录解析，跨目录调用务必传绝对路径。

附件扫描兜底（仅 MCP 拉不到的字段，如同名仅有告示牌/扫描件的维权电话等；同源第二取数途径。2026-10-21 起封面三方/现场负责人/项目经理/劳资专管员已由 `qxb_project_get` 结构化直出，不再依赖本通道）：

## 九·五、新项目接入自检（格式一致性验收）

新项目首次生成后，用"结构指纹比对"验收格式是否与既有报告一致（标题序列+表头序列，剔除待补充清单表）：

```python
from docx import Document
def fingerprint(path):
    doc = Document(path)
    heads = [p.text.strip() for p in doc.paragraphs
             if p.style.name.startswith('Heading') and p.text.strip()
             and p.text.strip() != '附：待补充数据清单']
    tables = ['|'.join(c.text.strip() for c in t.rows[0].cells)
              for t in doc.tables if [c.text.strip() for c in t.rows[0].cells][0] != '序号']
    return heads, tables, len(doc.inline_shapes)
# 与既有报告比对：heads 应完全相同；tables 除"仅在有数据时出现"的表（如线下考勤表）外应一致
```

验收要点：① 标题序列与基准报告零差异；② 表头序列除条件表外一致；③ 图数量差异能对应到数据缺口；④ 末尾《待补充数据清单》里每一项都清楚该找谁补。任一不满足即为格式回归，需排查而不是放过。
