## 🛠 6 步 SOP（每次"结构化"指令都跑）

### Step 1: 勘盘已落档原文（必跑 ⭐⭐⭐）

```bash
# 1.1 列出已落档法规 md 全文
ls -la ~/wiki/concepts/<分类目录>/*_全文.md

# 1.2 数条数（验证完整性）
for f in ~/wiki/concepts/<分类目录>/*_全文.md; do
  echo "=== $(basename $f) ==="
  grep -E "^第[一二三四五六七八九十百零]+条" "$f" | wc -l
done
```

**判定规则**：
- 每部法规条数与文末尾条（如"第二十四条"）匹配 = OK
- 条数对不上 = 跑 Phase 1 补档（不能结构化未落档的法规）

### Step 2: 建结构化目录 + README 索引（10 分钟）

```bash
mkdir -p ~/wiki/concepts/<业务名>法规结构化/
```

**README 必含 5 段**：
1. **老板定位**（用法 4 件套：全文检索 / 按条款速查 / 场景速查 / 跨法规对照）
2. **目录结构**（文件树 + 每个文件 1 行说明）
3. **源法规清单表格**（含文号 + 层级 + 本机原文路径）
4. **🔴 风险提示**（业务项目阶段必看的红线）
5. **引用铁律**（4 件套——rhzy-law-citation-strict 已固化）

**README 模板**：
```markdown
# <业务名>法规结构化索引（<项目名>专用）

## 老板定位：4 大用法
## 目录结构（6 文件树）
## N 部源法规清单表格
## M 大场景速查入口（最高频）
## 🔴 风险提示（<项目阶段>必看）
## 📌 引用铁律
```

### Step 3: 逐部法规切片（核心 ⭐⭐⭐）

**3 文件切片模板**（每部法规 1 文件）：

```markdown
# <法规名> - N 条逐条切片（<项目名>专用）

> 文号 / 发文机关 / 发布日期 / 施行日期 / 修订状态 / 本机原文路径

## 一句话总览（<项目阶段>必看）
## 总览表（N 条 → M 章节）
## 逐条切片（"原文 + 关键义务 + 项目落地"三段式）
  - 第 X 条
    - 原文：...
    - 关键义务：...
    - 云岭中心落地：🟢/🟡/🔴 + 具体动作
## 引用铁律
## 关联条款
```

**3 大设计原则**：
1. **三段式固定**：原文 → 关键义务 → 项目落地。**不能省任何一段**——老板后续查的是"我项目该干啥"
2. **红黄绿灯分级**：🟢 知晓 / 🟡 重点关注 / 🔴 必落
3. **每个 🔴 必带"<项目名>落地动作"**——不是抽象义务，是可执行清单

### Step 4: 跨法规对照表（核心 ⭐⭐⭐）

**1 文件对照表模板**：

```markdown
# <国版> vs <地方版> 同事项条款对照表

## 速查法规表（3-4 部法规元信息）
## 总对照表（按事项分类）
  - 事项 1: 适用范围
  - 事项 2: 概念定义
  - 事项 3: 建设单位义务
  ...
## 🔴 冲突点汇总（必看）
  - 冲突 1: <事项> —— <国版> vs <地方版> —— 就高从严走哪边
## 引用铁律
```

**对照表 5 大要素**：
1. **事项分类**（按业务方向，如"适用范围/建设单位义务/考勤保存期"）
2. **3-4 部法规 × 同一事项** 的条款对照（原文摘要 + 条号）
3. **对比判定**（🟢 一致 / 🟡 国版/地方版更严 / 🔴 冲突）
4. **就高从严走哪边**（明确处理原则）
5. **冲突点汇总表**（单列红框，老板一眼看全）

### Step 5: 场景速查表（最实战 ⭐⭐⭐）

**1 文件场景速查模板**：

```markdown
# <业务名> N 大场景速查表

## N 大场景（按出场频次排序）
  - A 场景: <名>
  - B 场景: <名>
  ...
## 每个场景 5 段式
  1. 主条款映射（地方版/国版 + 条号 + 原文摘要）
  2. 关键义务清单
  3. <项目阶段>必查动作清单（每月/每周/一次性）
  4. 处罚红线（条款 + 金额 + 后果）
  5. 责任人
## 0 容忍红线（汇总 N 条）
## 引用铁律
```

**场景速查 5 要素**：
1. **场景排序按频次**——老板最常查的排第一
2. **必查动作 = 月度 checklist**（N 项/月 + N 项/周 + N 项一次性）
3. **0 容忍红线**——单独汇总 10 条，老板一眼看全
4. **责任人明确**（总包 + 我方 + 监理 + 财务 等）
5. **处罚金额具体化**（"5-10 万罚款"而非"处罚"）

## ⚠️ 4 大 Pitfall（实战沉淀 · 2026-07-13）

### Pitfall 1: 切片时漏掉"修订状态"段

**反例**：
- 建市〔2019〕18号第八条已被建市〔2022〕59号修改
- 我切片 02 文件时**只写原文**没写"已被 XX 号修改"
- 老板后续查第八条 = 拿到的还是旧版"先签劳动合同后进场" → 用错

**正确做法**：
```markdown
> 修订状态：建市〔2022〕59号 修订后，第八条已替换；第十/十一/十二/十四条的"劳动合同"按"劳动合同或用工书面协议"理解
```

### Pitfall 2: 切片时只引国版不引地方版（漏掉地方规章）

**反例**：
- 国务院令 712 号《保障农民工工资支付条例》+ 建市〔2019〕18号 是上位法
- 但**实际处罚由贵州版（黔人社发〔2022〕18号第二十条）引到上位法第五十五/五十六条**
- 切片时只写"按国务院令 712 号处罚" → 漏掉贵州版的"转包挂靠红线"（第二十二条）→ 老板不知道有这个红线

**正确做法**：每个处罚条款必查贵州版/地方版是否**有引用 + 是否有地方额外红线**。三段式第 2 段（关键义务）必引地方版 + 国版双编号。

### Pitfall 3: 对照表"就高从严"只标不解释

**反例**：
- 我写"考勤保存期：就高从严走 3 年"
- 但**没解释**：国版 2 年 vs 贵州版 3 年 → 老板不知道为啥走 3 年 → 不知道如果总包只存 2 年要怎么应对

**正确做法**：每个"就高从严"必须写明——
- 国版原文摘要
- 地方版原文摘要
- **就高走的理由**（如"地方版比国版更严，且为地方规章 = 就高从严原则"）
- **如对方不执行的应对**（如"如总包只存 2 年 → 我方发函要求补存 + 留底"）

### Pitfall 4: 场景速查缺"每月 checklist"

**反例**：
- 我写"必查维权告示牌"
- 但**没写**每月/每周/一次性 + 谁查 + 怎么查
- 老板拿到表还是不知道"我项目监理工程师每月具体干啥"

**正确做法**：场景速查必须用 **表格形式**，列：动作 / 频次 / 责任人 / 验证标准。基坑阶段月度 checklist 至少 14 项/月 + 6 项/周。

**6 文件命名铁律**：
- 数字前缀 `01_/02_/...` 保证老板 ls 看到顺序
- 文件名必含法规文号（云岭中心用 `建市2022-59号` 而非"修订通知"）
- README 用 `README_` 前缀（Obsidian 索引友好）
